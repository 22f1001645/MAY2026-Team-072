<objective>
Ship the Brand kit section and the AI draft flow, then close the phase with the manual verification
the ROADMAP's criterion-4 observable requires.

Purpose: criterion 4 reads *"can request an AI-drafted starting kit, edit **every** field, and
nothing applies until they explicitly save it"*, and every state in this plan exists to make the
last clause observable. The structural decision that carries it is that a returned draft
**populates the live form fields in place** — a preview-then-apply flow would create a second write
surface and a second review moment, which is precisely the second-brand-kit-writer anti-pattern
this phase is built to avoid.

Output: `BrandKitEditor.tsx`, the Brand kit card wired into the page, and a blocking human
verification covering the six manual UAT behaviours no automated test can reach.
</objective>

Build S6. Implement the contract exactly; the notes below name the decisions most easily lost.

**Visibility (P-09).** The card renders **iff `canEdit`**, and the query is gated on the same value
so the request is never issued for a non-manager. Beyond the status code, a brand kit is an internal
working document for an organisation's own communications, not part of its public identity —
rendering an empty or errored card would advertise a surface the reader can never use.

**Read mode.** Voice/tone at `text-body` capped at `max-w-prose`; the palette as read-only 36px
swatches with their hex beneath at `text-caption`; sample phrases as a `space-y-2` list at
`text-[14px]`. Plus a `Badge tone="neutral"` **AI draft** in the header when `source === 'ai_draft'`
— provenance, not approval state: it means someone reviewed this and kept it, which is worth
recording and worth not over-explaining.

**Empty.** **No brand kit yet.** at `text-caption text-graytext-mid`, plus the **Edit** control and,
when `aiAvailable`, the **Draft with AI** control. **Not** an `EmptyState` primitive — this card is
one of three on a page and a full-height empty state would dominate a section that is genuinely
optional.

**Loading.** **Loading the brand kit…** at `text-caption text-graytext-mid` inside this card only.
It never blocks Profile or Links. A query failure renders **Could not load the brand kit.** with a
ghost **Retry** inside the card; the rest of the page is unaffected.

**Voice & tone.** `Textarea rows={3}`, placeholder **Warm, student-led, a little irreverent. Never
corporate.**, hint **A few words describing how your organisation sounds. The campaign writer reads
this.** Counter renders from 400 characters as **{n}/500**; past 500 it turns `text-red-300` and
reads **{n}/500 — trim {n−500} characters.** **No `maxLength`** — a hard cap silently truncates a
paste, and the user must always be able to see why.

**Palette.** Each row uses the shared row shell string, stacked at `space-y-2`, containing left to
right: a 36px swatch (`h-9 w-9 rounded-lg border border-white/20`, `style={{ background: value }}`)
with a full-size `<input type="color">` overlaid at `opacity-0 cursor-pointer` so **the swatch
itself is the picker** — one control, the platform's native colour UI, zero new dependencies — and
the input carries `aria-label="Pick colour {n}"`; then `Input className="flex-1"` holding the
lowercase hex, normalised to lowercase on blur; then a 36px remove button with
`aria-label="Remove colour {hex}"` and the same string as `title`.

**The picker and the text field write the same state**, and the text field is never removed, never
disabled and never made read-only — a native colour picker is not keyboard-friendly on every
platform, so typing is the accessible path and must always work.

The swatch border is `border-white/20`, **never teal** — teal chrome on a user's own colour would
misread as "selected". **A colour is data on this page, and that is exactly why colour is never the
only channel**: every swatch carries the outline so a near-black chip still reads as a square, and
its lowercase hex sits in an adjacent field which is the authoritative, copyable, screen-reader-legible
value. **The hex text, not the chip, is the value.** No contrast claim is made about a user's swatch —
it is content, not chrome, and nothing renders on top of it.

**Add a colour** appends an entry defaulting to `#ffffff` — visible against the dark surface and
obviously unset. At six entries the button is **absent** and the caption **Six colours is the
maximum.** renders in its place; a control that cannot be enabled without first removing something is
noise, and the caption is the explanation.

**Phrases.** The shared row shell at `space-y-2`: `Input className="flex-1"` plus a 36px remove
button with `aria-label="Remove phrase {n}"`. Counter from 160 characters as **{n}/200**, red past
200. No `maxLength`. **Add a phrase**; at ten entries the button is absent, replaced by **Ten
phrases is the maximum.**

**Blank rows are dropped from the payload** rather than sent — an empty row is a user who changed
their mind, not a value.

**Save.** **Save brand kit** plus a ghost **Cancel** at `mt-6 flex justify-end gap-2`. Save stays
enabled at all times. Success → `addToast('Brand kit saved', 'success')`, the section leaves edit
mode, and the read view re-renders from the server's response.

**Rejections** reuse 04-08's shape: heading from `code`, server's sentence verbatim beneath, field
gains `border-red-400/50`. The server enforces `^#[0-9a-f]{6}$`, so a typed `red`, `#ff` or
`rgb(1,2,3)` returns 422 `validation_error`; walk `details` to the indexed row and render
**Colours must be six-digit hex, like #5ce6c9** with the server's sentence beneath. When the index
cannot be resolved, render once at field level. Never render a raw serialised object.

**Destructive-action policy.** Removing a colour or a phrase gets **no confirmation** — removal
happens inside an unsaved section, nothing persists until **Save brand kit**, and **Cancel** restores
everything.

**Spacing.** Declared scale only — 4 / 8 / 16 / 24 / 32 / 48. **No `gap-3`, `mb-3`, `mt-3`,
`space-y-3`, `py-3` or `px-3`.** Every interactive element carries
`focus:outline-none focus-visible:ring-2 focus-visible:ring-teal/50`, including the `opacity-0`
colour input, which would otherwise swallow the focus indicator.

  <action>
Build S7. The structural decision is that a returned draft **populates the live form fields in
place**: no preview panel, no side-by-side diff, no modal, no Apply-draft button. Criterion 4
requires the user to edit *every* field, and a preview-then-apply flow creates a second write
surface and a second review moment. **`PUT /brand-kit` is the only writer and `Save brand kit` is
the only button that reaches it** (P-07).

**A0 — render-locked (`aiAvailable === false`).** **Draft with AI** as
`Button size="sm" variant="secondary"`, `disabled` **and** `aria-disabled="true"`,
`opacity-40 cursor-not-allowed`, a 12px padlock glyph immediately before the label, and a
**visible** line beneath at `text-caption text-graytext-light`: **AI drafting isn't set up on this
server. Fill the kit in yourself — every field below works without it.** — plus the same string as
`title`. Stays hoverable and focusable; **never `pointer-events-none`**. Never a bare disabled
button, never hidden, and never a 503 surfaced as a red error on page load.

This is the render-locked exception's **third trigger**, added by this phase and recorded in the UI
contract: *the control's absence would be indistinguishable from the feature not existing, and a
phase success criterion requires the feature be discoverable*. Hiding it when the server key is
unset would make ORG-04 untestable in UAT and would make a configuration problem look like a
missing product.

**A1 — available, no kit.** **Draft with AI** in the card header, caption **Gives you a starting
point. Nothing is saved until you press Save brand kit.**

**A2 — available, kit exists.** The control still renders, labelled **Draft a new version with
AI**, caption **This replaces what's in the form. Your saved kit isn't touched until you press Save
brand kit.** ORG-04's "for organisations that don't have one yet" scopes who the button is *for*,
not a hard gate; the endpoint is deliberately unconditional so a legitimate start-over is not
blocked, and a UI that hid the button after the first save would make that path unreachable with no
explanation. **When the form is dirty**, pressing it opens the S7-D confirm first; when pristine it
drafts immediately, because discarding restores the saved kit and there is nothing to lose.

**A3 — in flight.** Label → **Drafting…**, `disabled` **and** `aria-busy="true"` (never
`aria-disabled` — it is working, not unavailable), minimum 300ms visible. Every field in the Brand
kit card goes `disabled` for the duration; the Profile and Links sections do not. After **1200ms** a
caption appears beneath: **Still drafting — this takes a few seconds.** A **30-second client-side
abort** ends the request via the `AbortSignal` and routes to A5 with the generic heading.

**A4 — draft returned.** The fields fill in place, the section enters edit mode if it was not
already, and a **gold strip** renders directly above the field stack, **reusing Phase 2's banner
class string verbatim** (`flex items-start gap-3 rounded-xl border border-gold/25 bg-gold/[0.06] px-4 py-3`)
rather than authoring a new gold treatment — this is the phase's one and only gold surface, and no
second may be added. `role="status"` (**not** `role="alert"` — nothing is wrong). Title at
`text-[14px] font-semibold text-offwhite`: **This is an AI draft. Nothing is saved yet.** Body at
`mt-1 text-caption text-graytext-light`: **Edit anything below, then press Save brand kit. Discard
draft puts back what was there before.** Action in the strip: `Button size="sm" variant="ghost"`
**Discard draft**.

> The `gap-3` inside that lifted string is part of the inherited Phase 2 banner and comes across
> whole. It is **not** a licence for 12px anywhere else in this phase.

**The draft is atomic.** The strip covers the whole form; there is no per-field "from the AI"
marker. Six provenance captions scattered through a form is clutter, and once the user edits one
field the per-field claim stops being true anyway.

**The draft is never cached** (P-07). Not in a persisted React Query key, not in `localStorage`, not
in `sessionStorage`. It lives in component state and dies with the component. A draft that survived
a reload would be indistinguishable, to anyone reading criterion 4, from something having been
applied.

**A5 — failure.** An inline strip **above the Draft control** (never in the Save error slot, which
belongs to `PUT`): `rounded-xl border border-red-400/30 bg-red-500/10 px-4 py-3`, heading at
`text-[14px] font-semibold text-red-300`, body at `mt-1 text-caption text-red-300`. Heading chosen
from `code`, never by string-matching: `ai_unavailable` → **AI drafting isn't available right now**;
`ai_failed` → **The draft didn't come through**; anything else including the client abort →
**Could not draft a brand kit**. Body is the server's `message` verbatim; for the abort, **Nothing
changed. Try again, or fill the kit in yourself.** Every field keeps whatever it held and the button
re-enables. **Never toast-only.** On `ai_unavailable` specifically — meaning `aiAvailable` was stale
because the key was removed server-side mid-session — the button **also flips to A0 for the rest of
the session**, so a second click cannot repeat the same failure.

**S7-D — discard.** Restores the form to the last-saved kit, or to an empty form when
`hasKit === false`. The strip unmounts. **No request is sent and no toast fires** — nothing was ever
on the server to undo. An **untouched** draft discards immediately with no confirmation: the model's
words are not the user's work. An **edited** draft opens a single-step `Dialog max-w-md`: title
**Discard your edits?**, body **You've changed the draft. Discarding puts back {the kit you saved
earlier | an empty form}.**, actions ghost **Cancel** + danger **Discard draft**. The threshold is
the user's own typing, not the draft's existence.

**S7-N — navigation.** In-app navigation is **not blocked**: the draft is discarded and nothing is
saved, which is exactly what criterion 4 demands, and the disclosure happens *before* the loss in
the strip's own first sentence rather than as a confirm afterwards. There is no router blocker —
`useBlocker` requires a data router (`createBrowserRouter`) and this app renders `<Routes>` inside a
plain `<BrowserRouter>`; migrating is a framework change the standing no-new-frameworks constraint
forbids, and a hand-rolled interception would be a second mechanism competing with the router. This
is a recorded decision, not an omission. A `beforeunload` listener **is** registered while any
section is dirty and removed when it is not — the browser's own confirm costs two lines, needs no
router feature, and covers the one loss the user did not initiate through the app. **Exactly one
listener, owned by the page, never one per section.**

**Accessibility.** The gold strip is `role="status"` and the >1200ms caption announces inside it,
once. Every server-rejection strip is `role="alert"`. Dialog focus is trapped, returned to the
trigger on close, `Esc` and overlay click both cancel, and initial focus lands on **Cancel**.

**The AI provider is never named in user-facing copy.** The copy says **AI**; the provider is
swappable behind a lazy-import seam and a user-facing brand name would make a config change into a
copy change.
