<objective>
Build the schedule editor's two new-shape components: a row that saves itself on blur and can
be moved with keyboard-accessible arrow controls, and an inline preset accordion that
populates a whole agenda in one click.

Implements D-02: scale-appropriate presets shown as inline accordion rows — each preset
expands to preview sample items; clicking it populates the schedule list (`PresetAccordion`).

Purpose: DESIGN-01's UI is the largest genuinely new frontend shape in this phase.
`grep -rn "onBlur" frontend/src/` and `grep -rni "moveUp|moveDown|reorder" frontend/src/` both
return zero matches — verified twice. CONTEXT.md's D-01 and D-03 describe these as reuses of
the `ProposalNew.tsx` budget-row pattern; that pattern is add-and-remove only, with a single
submit at the end. What genuinely transfers is the repeating-row layout and the `+ Add …`
ghost button. Everything else here is new code, and this plan is sized for that.

Output: `ScheduleRow.tsx`, `PresetAccordion.tsx`, their vitest specs, and a CampaignBuilder
page that uses them.
</objective>

**`ScheduleRow.tsx`** — props exactly as UI-SPEC §2.2 declares: `item`, `onUpdate(id, patch)`,
`onDelete(id)`, `onMoveUp(id)`, `onMoveDown(id)`, `isFirst`, `isLast`, `disabled?`.

Internal state is deliberately minimal: a `draft` object seeded from `item` for the fields
being edited, a `saving` boolean, and a `lastSaved` snapshot used for the revert. Server state
still lives in TanStack Query — `draft` exists only for the span between keystroke and blur.

Blur handling: on `onBlur` of the time-block, title or notes field, compare the field's current
value with `lastSaved`; if unchanged, do nothing; if the title is empty or whitespace, restore
`lastSaved` and do nothing; otherwise set `saving` true and call `onUpdate(item.id, { <that
field only> })`. Send one field, not the whole row — plan 05-01's PATCH treats a payload
carrying only `position` as a reorder, and a whole-row replace from a stale draft would
clobber a concurrent move. On resolve, update `lastSaved`, clear `saving`, and show the
`Saving…` caption for 800 ms before fading it out over 500 ms (`opacity` transition, not a
layout change). On reject, restore the field to `lastSaved` and call
`addToast('Failed to save', 'error')`.

Layout per UI-SPEC §2.2: `flex items-start gap-3 group py-3 border-b border-divider`; a
`flex flex-col gap-0.5` column of two ghost icon-buttons for up/down; the time-block `Input`
`w-32 shrink-0` with placeholder `10:00–10:30`; the title `Input` `flex-1 truncate` with
placeholder `e.g. Opening remarks`; a `+ notes` caption button toggling a `Textarea` below with
the same blur-save behaviour; and a danger ghost delete button revealed on `group-hover`. Give
the up/down/delete buttons `aria-label` values `Move up`, `Move down` and `Delete schedule
item` (UI-SPEC §7). When `disabled` is true, render neither the reorder pair nor the delete
button and mark the inputs read-only — the server already returns 409 `campaign_live`, and this
is the matching affordance, not the enforcement.
