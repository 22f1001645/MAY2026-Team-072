<objective>
Fix the frontend's data contract and its session-expiry surface — the two standards violations found in the 2026-08-12 review that every later Phase 2 and Phase 3 screen would otherwise inherit.

Backend responses are snake_case; `frontend/src/lib/types.ts` holds the camelCase shapes pages render; `lib/api.ts` is the single place adaptation is allowed to happen. `api.me()` is currently typed `request<any>` and passes raw snake_case straight through, so `capabilities.is_organiser` and `currentUser.academic_status_stale` are read directly inside three components. The UI-SPEC was written against `capabilities.isOrganiser` and `capabilities.academicStatusStale`, so the code and the design contract disagree today.

Purpose: D-10 calls the capability payload "a published response contract that Phase 5's live workspace pages will build against". Publishing it in the wrong casing, un-adapted, is the version of that contract that is expensive to change later.

Output: one adapter, camelCase types, every consumer updated, a router-state session-expiry surface, and the first frontend test of the session contract.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API response → typed client model | An untyped `any` passthrough lets wire-shape changes reach rendering code silently |
| URL query string → session-state UI | A query parameter is user-controllable, bookmarkable and shareable; treating it as session truth lets a crafted link assert a state that is not real |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Information disclosure | access token storage | high | mitigate | Access token stays in a module variable; the legacy `ekatva_token` key is purged and Task 3 asserts it is never written again |
| T-02-07 | Elevation | capabilities used as an authorization decision | critical | mitigate | Capabilities remain render-only; no client control is granted by them, and every mutating call is still authorised server-side by the Phase 1 scoped guards |
| T-02-28 | Spoofing | `?expired=1` as session-state input | low | mitigate | Notice moved to router state, so a crafted or bookmarked URL can no longer assert an expiry that did not happen. NEW threat, found in the 2026-08-12 audit |
| T-02-29 | Denial of service | poisoned single-flight promise | medium | mitigate | Cleared in a `finally`; Task 3 pins it with a mutation-verified test. A cached rejected promise would fail every later request without retrying |
| T-02-10 | Elevation | stale capability snapshot | medium | accept | Worst-case staleness is one `/auth/me` cache window; D-11 accepts this explicitly and revocation is never gated on it |
</threat_model>
