**`PushLiveGate.tsx`** — props `status: string`, `isMeetupHead: boolean`,
`pushedLiveAt: string | null`, `onPushLive: () => Promise<unknown>`, `publishing: boolean`.

Live state first: when `status` is the live value, render only
`<Badge tone="success">Campaign Live ✓</Badge>` plus `Pushed live on <date>` in
`text-body text-graytext-light`, and no button at all. `Badge` here is a static label, which is
all it supports.

Otherwise render the gate card — `Card p-6 border border-teal/20 bg-teal-deep/10`, heading
`Ready to go live?` in `text-h3 text-gold`, and a `text-body text-graytext-light` sub-line
describing what publishing does.

For the Meetup Head: `Button variant="primary" size="lg"` labelled `Push Live`, opening the
`Dialog` primitive titled `Publish Campaign?` with the body `This will make the event visible
to students. The Kanban workspace will activate.` and Confirm / Cancel buttons. Confirm calls
`onPushLive`; while `publishing`, the confirm control is disabled and reads `Publishing…`, and
nothing navigates.

For everyone else: the same button, visually identical, but with `aria-disabled="true"` and a
no-op click handler, wrapped in a `<div title="Only the Meetup Head can publish">` for the
native tooltip, with the note `This action requires the assigned Meetup Head.` beneath it in
`text-caption text-graytext-mid`. Use `aria-disabled` rather than the `disabled` attribute
(UI-SPEC §7) so the control stays keyboard-focusable and the tooltip stays reachable — a
`disabled` button is skipped by tab order and its tooltip becomes unreachable, which would
defeat the entire point of D-07's visible-but-blocked design.

`isMeetupHead` comes from the server payload. Do not derive it from
`capabilities.manageableActivityIds`: that answers whether the user can manage the activity,
which is true for every crew member, and would render the button enabled for exactly the people
the server will refuse. The refusal itself is enforced by `@meetup_head_required` (plan 05-03)
regardless of what this component renders.

On a rejected `onPushLive`, raise `addToast('Only the Meetup Head can publish', 'error')` when
the caught `ApiError`'s status is 403, and re-enable the control.

**Wiring in `CampaignBuilder.tsx`:** render the gate in a Publish section at the bottom, fed
from the campaign payload's `status`, `isMeetupHead` and `pushedLiveAt`. On a successful push,
raise `addToast('Campaign is now live!', 'success')`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server campaign payload → rendered permissions | `is_meetup_head` and `completeness` are advisory rendering inputs; the server is the authority for both |
| confirmation dialog → publication | The last reversible moment before students can see the event |

## STRIDE Threat Register (ASVS L1, block on high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-38 | Elevation of Privilege | the disabled button mistaken for the enforcement | high | mitigate | `@meetup_head_required` is the control and AC-25's negative control proves it independently of the client; the component's own spec asserts the client-side refusal separately so both layers are tested |
| T-05-39 | Spoofing | a tampered `is_meetup_head` flag enabling the button | medium | accept | An attacker who can rewrite the response can already rewrite the DOM; the server refuses regardless. Documented rather than defended client-side |
| T-05-40 | Tampering | accidental publication with no confirmation | medium | mitigate | The `Dialog` confirmation is required before the mutation fires; asserted by the "fires the mutation zero times until Confirm" behaviour |
| T-05-41 | Information Disclosure | a partial stepper rendering stale completeness after a failed fetch | low | mitigate | The parent renders `ErrorState` for the whole page instead of the stepper when the campaign query fails (E1 backstop) |
| T-05-42 | Denial of Service | a keyboard user unable to discover why publishing is blocked | low | mitigate | `aria-disabled` rather than `disabled`, so the control stays in tab order and the tooltip is reachable |
| T-05-SC | Tampering | package-manager installs | high | accept | This plan runs no `npm install`; Phase 5 adds zero dependencies |
</threat_model>
