## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `/api/v1/activities/<id>/tasks` | Crew-authored task text crosses here and is rendered back to other crew members |
| campaign live state → workspace visibility | TEAM-01's gate; the client presents it, the server enforces it |

## STRIDE Threat Register (ASVS L1, block on high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-43 | Tampering | stored XSS via a task title or assignee name rendered onto a card | medium | mitigate | Values render as React children and as `title` attributes only; no `dangerouslySetInnerHTML` and no `innerHTML` assignment is introduced |
| T-05-44 | Information Disclosure | a board rendering before publication | high | mitigate | The server returns 403 `campaign_not_live` for every task route (plan 05-04, T-05-21); the page presents that as an explanation and renders no board |
| T-05-45 | Denial of Service | a polling loop hammering the dev server and defeating AC-35 | medium | mitigate | The `no-kanban-polling` source scan with a positive control, running in the standard `npm test` suite |
| T-05-46 | Information Disclosure | a hardcoded POR or team-role string leaking the authorization model into the client | medium | mitigate | Roles and statuses come from the server payload; `no-por-literals.test.ts` runs in every task's verify block here |
| T-05-47 | Tampering | a stale card overwriting a concurrent edit to the same task | medium | accept | Last-write-wins is the sanctioned resolution (SPEC § Edge Coverage, TEAM-02 concurrency, backstop). The status control sends the status alone, which bounds the blast radius to one field |
| T-05-SC | Tampering | package-manager installs | high | accept | This plan runs no `npm install`; D-09 explicitly rules out a drag-and-drop library and Phase 5 adds zero dependencies |
</threat_model>
