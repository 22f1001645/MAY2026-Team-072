<objective>
Build the local-filesystem upload primitive: a hardened `POST /orgs/<org_id>/logo` and a public,
`nosniff`-headed serve route.

Purpose: this repository has **zero** upload code — no `request.files`, no `secure_filename`, no
`UPLOAD_FOLDER`, no `send_from_directory` anywhere (04-PATTERNS.md § No Analog Found). Every
control here is built from nothing, and Phase 5's CAMPAIGN-03 reuses the identical primitive, so
the cost is shared rather than duplicated. This is where the phase's file-handling security budget
goes.

Output: `upload_bp`, the serve route, the org-scoped upload endpoint, logo removal through the
existing profile PATCH, and the security test battery.

  <action>
Create the serve half of the primitive and the sniffing helper the write half will call.

**Config (`backend/app/config.py`).** Add to the `Config` class body, following the existing
`os.getenv(NAME, default)` shape with a comment where the default is a decision:
`MAX_CONTENT_LENGTH = 2 * 1024 * 1024`. Flask rejects a body larger than this **before buffering
it**; a per-view length check has already read the whole body into memory before it can reject.
Do not override it in `TestConfig` — the size-cap test needs the real value. Also add
`GEMINI_API_KEY = os.getenv("GEMINI_API_KEY")` and
`GEMINI_MODEL = os.getenv("GEMINI_MODEL", "gemini-2.5-flash")` now, so 04-05 does not have to
re-touch this file; `None` for the key means the feature is off.

**Upload directory.** A module-level `upload_dir()` in `upload_controller.py` returning
`Path(current_app.instance_path) / "uploads"` and calling `mkdir(parents=True, exist_ok=True)`
on it. Resolve it at call time, never at import time, and never assume it exists — `instance/`
is gitignored so it is absent on every fresh clone and in CI.

**Sniffing.** `IMAGE_MAGIC`, a tuple mapping each accepted signature to its canonical extension:
PNG `\x89PNG\r\n\x1a\n` → `.png`; JPEG `\xff\xd8\xff` → `.jpg`; WEBP, which is `RIFF` at offset 0
**and** `WEBP` at offset 8 → `.webp`. `sniff_image_ext(head: bytes) -> str | None` returns the
extension or `None`. The decision is made from the bytes alone: the multipart part's declared
content type and its filename are both fully client-controlled and are discarded. **SVG, GIF and
everything else return `None`.** SVG is excluded deliberately — it is an XML document that can
carry executable content, and serving one from the API origin is stored XSS (D-01).

**Serve route.** `upload_bp = Blueprint("uploads", __name__, url_prefix="/api/v1")` and
`@upload_bp.get("/uploads/<filename>")` with **no guard**. Serve with
`send_from_directory(upload_dir(), filename)`, then set `X-Content-Type-Options: nosniff` on the
response before returning it. `send_from_directory` refuses traversal by design; do not
hand-roll an `os.path.join` plus a `..` check, which misses percent-encoded and
Windows-separator variants — and this project develops on Windows, where Phase 1 already hit a
platform path bug. Return 404 for a missing file.

**The route is unauthenticated on purpose, and the reason is a browser constraint, not laziness.**
The SPA runs on `:5173` and the API on `:5000`, so a plain `<img src="http://localhost:5000/api/v1/uploads/x.png">`
is a cross-origin subresource load: it sends no `Authorization` header (the access token lives in
memory, not in a cookie the browser could attach) and no cookies. A guarded logo URL renders as a
broken image in every browser. This path contains no `<org_id>`, so
`tests/test_rbac_enforcement.py`'s `SCOPED_PARAMS` walk does not require a guard on it, and no
entry may be added to `LEGACY_COARSE_ROUTES`.

Per P-01, the unguessable filename is **not** the control — it exists because credentials cannot
travel on that request. The controls are the size cap, the sniff, the format allowlist and
`nosniff`, and none of them may be relaxed because the URL is hard to guess. State that in the
route's docstring.

**Registration.** Add `from .upload_controller import upload_bp` to the import block **and** an
`upload_bp` entry to `ALL_BLUEPRINTS`. This phase adds two controller files, which is exactly the
asymmetry that cost Phase 2 an endpoint; `test_blueprint_registration.py` from 04-01 is the net.

**Tests.** Add to `backend/tests/test_org_profile_brand_kit.py`: write a real PNG byte string to
`upload_dir()` in the test, then assert `GET /api/v1/uploads/<name>` returns 200 **with no
Authorization header**, that the response carries `X-Content-Type-Options: nosniff`, and that a
traversal attempt (`../../ekatva.db` and its percent-encoded form) does not return 200. Name the
test so the `04-VALIDATION.md` selector `uploads_public_no_traversal` resolves.
  </action>

    - Valid JPEG and valid WebP bytes → 200.
    - SVG bytes → 400 `invalid_image`; no file is written.
    - Bytes that are not any accepted image, sent with the filename `logo.png` and a declared content type of `image/png` → 400 `invalid_image`; no file is written.
    - A body of exactly `MAX_CONTENT_LENGTH` is accepted at the transport layer; one byte over is refused with 413 before the view function runs.
    - A second upload replaces the first: the row points at the new file and the old file is gone from disk.

Add the write half.

**Schema.** Extend `OrgProfileSchema` with
`logo_url = fields.Str(required=False, allow_none=True, validate=validate.Length(max=300))` so
`PATCH /profile` can clear it with an explicit null. There is no separate delete endpoint
(UI-SPEC S3). Reject any *non-null* client-supplied `logo_url` that is not a path this server
issued — the only legitimate writer of a non-null value is the upload endpoint, and accepting an
arbitrary string here would reintroduce the external-hotlink shape D-05 rejected. Validate it
against the served-path prefix and the uuid-plus-extension pattern.

**Service — `store_logo(org, file_storage, actor)`.** Read only the first 16 bytes for the sniff,
then `seek(0)` before saving. `ext = sniff_image_ext(head)`; if `ext is None` raise
`ApiError("That file isn't a PNG, JPEG or WebP.", "invalid_image", 400)`. Build the name as
`f"{uuid4().hex}{ext}"` — the extension comes from the **sniffed** type, never from the client's
name. Save into `upload_dir()`. Capture the previous `logo_url` before overwriting, set the new
served path on the org, write
`AuditRepository.record("organisation", org.id, "Updated organisation logo", actor)`, then one
`db.session.commit()`, and **only after the commit returns** unlink the previous file if it was a
path this server issued. Delete-after-commit so a rollback never orphans the row's image;
unlink failures are logged and swallowed, never surfaced as a request error.

The same after-commit unlink applies when `PATCH /profile` sets `logo_url` to null.

**Controller.** `@org_profile_bp.post("/orgs/<org_id>/logo")` with `@can_manage_org_required`.
Read the part from `request.files`; a missing part is `400 invalid_image` with a message naming
the expected field. Return the same profile payload shape the other endpoints return. The
parameter is `org_id`.

**The 413 path.** Flask raises `RequestEntityTooLarge` before the view runs, and the existing
`HTTPException` handler in `errors.py` already converts it into the JSON envelope. Do not add a
per-view length check — that check has already buffered the body. Assert the 413 in a test rather
than implementing anything for it.

**Do not trust the declared content type of the multipart part, and do not derive the extension
from the submitted filename.** Both are fully client-controlled. `secure_filename()` is not the
defence here: it can return an empty string and it does nothing about content-type confusion.
The only filename that cannot be attacked is one the client never supplied.

**Tests.** Add to `backend/tests/test_org_profile_brand_kit.py`, named so the `04-VALIDATION.md`
selectors resolve: `logo_upload_png`, `logo_rejects_svg`, `logo_sniffs_content`,
`logo_too_large`, plus a replace test asserting the old file is gone, a removal test for
`logo_url: null`, and a cross-org 403. Construct multipart bodies with `io.BytesIO` and the
`data={"file": (BytesIO(...), "logo.png")}` form; for `logo_sniffs_content` send non-image bytes
under the name `logo.png` with `content_type="image/png"` so the test proves the sniff, not the
extension, is what decides.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Flask API (multipart) | The request body, the declared content type and the filename are all fully client-controlled. |
| Flask API → local filesystem | A server-generated name is written under the instance folder; nothing client-supplied reaches the path. |
| local filesystem → any browser (public route) | The serve route is reachable without credentials and must not be able to return an active document. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-17 | Tampering | SVG upload → stored XSS | high | mitigate | Format allowlist is PNG/JPEG/WebP by magic byte; SVG and GIF return `None` from `sniff_image_ext`. Asserted directly on the helper and through a 400 `invalid_image` integration test. |
| T-04-18 | Tampering | content-type confusion | high | mitigate | The extension is derived from the sniffed signature; the declared content type and the client filename are discarded. `logo_sniffs_content` sends non-image bytes as `logo.png` / `image/png` to prove it. |
| T-04-19 | Tampering | browser re-sniffing a served file into HTML | high | mitigate | `X-Content-Type-Options: nosniff` on the serve route, asserted in the test. |
| T-04-20 | Information Disclosure | path traversal on serve | high | mitigate | `send_from_directory` from the instance folder, which is outside `static/`; the served name is always server-generated. Hand-rolled path checks are explicitly forbidden. |
| T-04-21 | Denial of Service | oversized upload | high | mitigate | `MAX_CONTENT_LENGTH = 2 MiB`, which Flask enforces before buffering the body; the existing `HTTPException` handler turns the 413 into the standard JSON envelope. Boundary test at exactly the cap and one byte over. |
| T-04-22 | Denial of Service | unbounded disk growth on replace | medium | mitigate | The previous file is unlinked after the commit succeeds; unlink failure is logged and swallowed. |
| T-04-23 | Information Disclosure | enumeration of the public serve route | low | accept | The route is unauthenticated because a cross-origin `<img>` can carry no credentials. Names are `uuid4().hex`, and the only content served is an organisation logo the app already shows to every logged-in user. Accepted explicitly — and per P-01 the unguessable name is not counted as one of this phase's controls. |
| T-04-24 | Elevation of Privilege | cross-org logo write | high | mitigate | `can_manage_org_required` on `POST /orgs/<org_id>/logo`, with a 403 assertion in this plan's tests. |
| T-04-25 | Tampering | client writing an arbitrary `logo_url` through `PATCH /profile` | medium | mitigate | A non-null `logo_url` is validated against the served-path prefix and the uuid-plus-extension pattern; only null and server-issued paths are accepted. |
