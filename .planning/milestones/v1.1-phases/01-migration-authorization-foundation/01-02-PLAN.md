<assumption_delta_decision>
The `assumption-delta scan` detector fired for Phase 1 (`detected: true`, kind `pluralization`). The substantive identity-model change is in this plan: an Activity's owning organisation goes from singular to plural.

- **Noun now primary:** `activity_collaborators` (the set of organisations on an Activity, each with a `status` and at most one flagged `is_primary`).
- **Decision:** **promote** — `activity_collaborators` becomes the source of truth for "which organisations are running this activity", and the pre-existing `activities.org_id` column is demoted to a denormalised pointer that must always equal the `org_id` of the row where `is_primary` is true. `activities.org_id` is NOT dropped and NOT made nullable.
- **Rationale:** Promotion is correct because a single FK genuinely cannot express PROPOSAL-01's many-to-many with per-collaborator consent state (PROPOSAL-06) — the general representation must be primary or every downstream count (PROPOSAL-03's Mega Meetup label, PROG-02's fest threshold) has to special-case the owner. Demotion rather than removal is correct because `activities.org_id` is non-nullable today and is read by `Activity.org`, `Activity.to_dict()`, `ActivityRepository`, `org_service`, `analytics_service` and the seeded demo data; dropping it in a foundation phase would turn a schema plan into a cross-cutting refactor with no user-visible gain. Phase 3, which owns PROPOSAL-01, is responsible for writing both sides whenever a proposal is created and for keeping them consistent. This is explicitly a promote, not an add-alongside: new code reads collaborators, and `org_id` survives only as a cache of the primary.
</assumption_delta_decision>
