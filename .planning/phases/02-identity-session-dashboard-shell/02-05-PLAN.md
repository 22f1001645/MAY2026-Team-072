<objective>
Make AUTH-04's admin override reachable and correct, and prove the decoupling promise that is the requirement's entire point.

Two independent defects currently make D-22 impossible to exercise: the blueprint carrying the admin override endpoint is **never registered**, so the route 404s; and the service that would write the audit row constructs `AuditLog` with keyword arguments the model does not have, so it would raise `TypeError` even if it were reachable.

Purpose: AUTH-04 says academic status is "fully decoupled from session/login behavior". That decoupling is a negative claim, and negative claims only hold if something tests them.

Output: a routable, validated, audited admin override; staleness proven against the real `terms` table; the decoupling guarantee under test; and the Phase 2 migration verified on a populated database.
</objective>

**Already correct — do not rebuild:**
- The academic columns `academic_level`, `academic_status`, `academic_confirmed_at` already exist on `User`, landed by Phase 1's `213804635519`. 02-CONTEXT.md D-23 overstated this; 02-RESEARCH.md corrected it.
- `ACADEMIC_LEVELS = ("foundation", "diploma", "degree")` and `ACADEMIC_STATUSES = ("active", "on_break", "withdrawn")` already exist in `constants.py` and match the UI-SPEC enum table exactly.
- The `terms` table exists (migration `e23b8dff512c`) with `is_current` added by `17240eb59839`. The chain is single-headed: `213804635519` → `e23b8dff512c` → `17240eb59839`.
- `seed.py`'s `seed_reference_data()` already creates the `May 2026` term with `is_current=True`, idempotently and without the destructive guard — D-24 is satisfied.
- `PATCH /api/v1/auth/academic-status` (self-confirm) is registered on `auth_bp` and works.
- The full backend suite currently exits 0, including `tests/test_migrations.py`.

**Four real defects, all in scope here:**

1. **The admin override endpoint is unroutable.** `auth_controller.py` defines `_admin_bp = Blueprint("admin_auth", __name__, url_prefix="/api/v1/admin")` and hangs `admin_update_academic_status` on it — but `controllers/__init__.py` imports only `auth_bp` and `ALL_BLUEPRINTS` never lists it. `PATCH /api/v1/admin/users/<user_id>/academic-status` returns 404. The leading underscore in the name is itself the reason it reads as private and was skipped.

2. **The audit write would crash.** `auth_service.admin_override_academic_status` builds `AuditLog(entity_type="user", entity_id=..., action=..., actor_id=..., changes={...})`. The model declares `entity`, `entity_id`, `action`, `actor_id`, `actor_name`, `note` — there is **no `entity_type` and no `changes`**, so SQLAlchemy raises `TypeError: 'entity_type' is an invalid keyword argument for AuditLog`. 02-RESEARCH.md's guidance stands: encode old and new into `note` as a small JSON string rather than widening the shared audit table.

3. **Validation is inline, not Marshmallow.** Both academic-status views read `request.get_json()` raw and the service compares against hardcoded tuples that duplicate `constants.ACADEMIC_LEVELS` / `ACADEMIC_STATUSES`. The project's cross-cutting pattern is Marshmallow → 422. `admin_update_academic_status` also returns a hand-built `jsonify({"error": ..., "code": "not_found"}), 404` instead of raising `ApiError`, bypassing the uniform envelope.

4. **A latent type mismatch in the terms data.** `Term.start_date` and `Term.end_date` are `db.DateTime`, but `seed.py` inserts `datetime(2026, 5, 1).date()` — `date` objects. `is_academic_status_stale` compares those bounds against a `datetime`. Comparing `date` to `datetime` raises `TypeError` in Python; SQLite's permissiveness is the only reason this has not surfaced. Task 2 must exercise staleness against a **seeded-shaped** term row, not only against a test row built with `datetime` values, or the test will pass while the running app fails.

Also note `is_academic_status_stale` returns `False` when no current term exists — a deliberate fail-open (nobody is nudged rather than everybody). Keep the behaviour; make it explicit with a test and a docstring.

**Out of scope, present in the tree:** the "Phase 9 admin analytics" feature from commit `f2c127e`. Do not extend or test it.
