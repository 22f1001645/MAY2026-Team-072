<objective>
Ship the organisation profile page: its shell, its gating, the logo control and the single logo
renderer every surface in the app now goes through.

Purpose: this is the first surface in Ekatva OS where a user's own words and a user's own image
bytes are rendered back to other people. The page's whole job is to make *what the server actually
vouches for* the thing that reaches the screen, and to make everything the server refuses **absent
rather than broken**. ORG-01's "across all four org types" is discharged by there being nothing to
branch on — one component, one layout, one field set.

Output: `OrgLogo.tsx`, `OrgProfile.tsx`, the `Textarea` primitive, the route and nav entry, and
the `/admin/orgs` reconciliation that retires `HOUSE_META` as a *source* while keeping it as a
*fallback*.
</objective>

  <action>
Build the page, register it, and give it its two entry points. Implement S1, S2 and S3 exactly as
the UI contract specifies; the notes below name only the decisions most likely to be lost.

**Structure.** Identity header (`flex items-center gap-4`: the 80px `OrgLogo`, then `SectionTitle`
with eyebrow **Organisation** and the org name, then a `flex flex-wrap gap-2` badge row carrying
the type label — **Forest House** / **Society** / **Region** / **Council** — and, when `city` is
set, a neutral `Badge`), then `mb-8`, then a `space-y-6` column of three `Card className="p-6"` in
the **locked** order **Profile → Links → Brand kit**. This plan builds the Profile card and leaves
declared, empty mounting points for Links (04-08) and Brand kit (04-09).

`space-y-6` owns every gap between sections; no section adds a margin of its own. Inside a card:
header row at `mb-4 flex items-center justify-between`, field stack at `space-y-4`, action row at
`mt-6`. **No new `gap-3`, `mb-3`, `mt-3`, `space-y-3`, `py-3` or `px-3` may appear anywhere in this
phase** — this phase's inherited-12px list is empty, and the `Textarea` primitive's `px-4 py-3` is
the one exception, inherited verbatim inside the primitive.

**One component, four types.** Read `org.type` for exactly two things: the type `Badge` label and
whether the HOUSE_META rung is eligible (which `OrgLogo` already owns). **Branch on it nowhere
else** — no per-type layout, no per-type field set, no per-type copy.

**Gating (S2).** `const canEdit = capabilities.manageableOrgIds.includes(orgId)`, computed **once**
at the top and passed down. Never recomputed per section, never combined with `role === 'admin'` at
the call site — admin authority already arrives inside `manageableOrgIds`, computed server-side.
Never derived from a POR string; `src/__tests__/no-por-literals.test.ts` scans for POR literals
with a frozen one-file allowlist and `OrgProfile.tsx` must never be added to it. The value is
never sent to the API.

**A non-manager sees the complete, unremarkable read-only profile and nothing else** — no Edit
control, no greyed control, no padlock, no permission line, no Brand kit card (P-06).

**Per-section editing.** Each section owns its own **Edit**, its own **Save**/**Cancel** and
exactly one endpoint. There is no page-level edit mode and no page-level Save: a single Save
spanning three endpoints has four partial-failure states with no honest way to report them. Edit
state is local component state (`editing: 'profile' | 'links' | 'brandkit' | null`), **not** a URL
parameter — an `?edit=1` URL a non-manager could paste would render a page with no editable fields
and read as broken. At most one section edits at a time; the other two sections' **Edit** controls
go render-locked with **Finish editing {section} first.**

**Render-locked is a specific visual contract**, not a bare `disabled`: `disabled` **and**
`aria-disabled="true"`, `opacity-40 cursor-not-allowed`, a 12px padlock glyph immediately before
the label, a **visible** line beneath at `text-caption text-graytext-light` plus the same string as
`title`, label unchanged, and **never `pointer-events-none`** — it stays hoverable and focusable.
Busy is the opposite contract: `disabled` **and** `aria-busy="true"`, no padlock, label swapped to
the present participle (**Saving…**, **Uploading…**, **Removing…**), 300ms minimum visible. Never
both, never in the same frame.

**Save stays enabled at all times.** **Save changes** is never pre-disabled on a client-side guess
of a server rule. Every rule on this page lives on the server by design, and a client that
pre-disabled on its own copy would be a second, weaker validator whose first disagreement leaves
the user facing a grey button with no explanation. This is the rule most likely to be "helpfully"
broken during implementation; it is deliberate.

**Mid-edit capability loss** is the one place the render-locked exception applies to authority: if
a refetch removes the org from `manageableOrgIds` while a section is open, the section stays open
with its values intact and **Save** goes render-locked with **Your access to this organisation
changed. Copy anything you need — this won't save.** Silently discarding a half-written bio is
worse than an honest dead end.

**Profile card.** The 80px `OrgLogo` with the upload control beneath it in edit mode, and the bio.
Bio uses the new `Textarea`, with a counter appearing from 800 characters and turning `text-red-300`
past 1000 reading **{n}/1000 — trim {n−1000} characters.** No `maxLength` — a hard cap silently
truncates a paste. Read view: the bio at `text-body`, capped at `max-w-prose`; when absent,
**{Org name} hasn't written a bio yet.** at `text-caption text-graytext-mid`.

**Upload control (S3).** A visually-styled `<label>` wrapping a visually-hidden
`<input type="file" accept="image/png,image/jpeg,image/webp">`. The label is the focusable,
keyboard-activatable control and carries the teal focus ring — a hidden input with a `<div>`
trigger is not keyboard-reachable and is forbidden. Label reads **Upload a logo**, or **Replace
logo** when rung 1 is live. The request fires **on file choose**; there is no second press and no
staging. An object-URL preview renders immediately at `opacity-60` with `aria-busy="true"` on the
control, is replaced by the server's URL on success and revoked, and on failure is **discarded** so
the tile snaps back to whichever rung was live — never leaving a preview of a file the server
refused.

Client-side rejections send **no request**: over 2 MB → **That file is {size} MB. The limit is
2 MB.**; a type outside the three → **PNG, JPEG or WebP only. SVG isn't accepted.** The `accept`
attribute is a hint, not a gate. These are immediate explained rejections of an input that provably
cannot succeed, which is why they do not violate the never-pre-disable rule.

Server rejections choose their heading from the envelope `code`, never by string-matching the
message, using the module-level `Record<string, string>` + fallback-helper shape from
`ProposalNew.tsx`: `invalid_image` → **That file isn't a PNG, JPEG or WebP** with the server's
sentence verbatim beneath; a 413 renders the same copy as the client-side size rejection.

**Remove logo.** A 36px icon-only control on the tile in edit mode, rendered **only when rung 1 is
live**, with `aria-label="Remove the logo"` and the same string as `title`. It opens a single-step
`Dialog` whose body names the true outcome by asking the ladder what rung 2 would produce — **{Org
name} goes back to {the built-in {House name} mark | its initials}. You can upload a new one any
time.** — with `Cancel` / `Remove logo`. It writes `PATCH /profile` with `logo_url: null`; there is
no separate delete endpoint.

**Fallback disclosure is edit-mode only.** **Using the built-in {House name} mark** or **No logo
yet. {Org name} shows its initials.** appears beneath the tile in the Profile card in edit mode.
Nothing marks the fallback on the read view — that would make the entire Houses grid look
unfinished on day one.

**Org switcher.** A `Select` at the identity header's right edge, rendered **iff**
`manageableOrgIds.length > 1` **and** `manageableOrgIds.includes(orgId)`.

**Errors.** A 404 renders a dedicated `Card p-6 py-12` centred — heading `text-h3` **That
organisation doesn't exist.**, body **The link may be out of date.**, `Button variant="ghost"`
**Back to Discover** — not the generic `ErrorState`, whose alarm language would misdescribe what is
almost always a stale link. Anything else renders the existing `ErrorState`.

**Accessibility.** One `h1` (the `SectionTitle`) and three `h2` section headings; the badge row is
not a heading. Every interactive element carries
`focus:outline-none focus-visible:ring-2 focus-visible:ring-teal/50`, without exception, including
the hidden file input's styled label. Every icon-only control is at least 36px and carries an
`aria-label` **and** the same string as `title`. Dialog focus is trapped, returned to the trigger on
close, `Esc` and overlay click both cancel, and initial focus lands on **Cancel**. Server-rejection
strips are `role="alert"`.

**Responsive.** Single column at every width; the identity header wraps to `flex-col items-start`
below `sm` with the tile above the title. The 80px tile does not shrink on mobile. Bio text caps at
`max-w-prose`.

**Route (`App.tsx`).** Import beside `import Orgs from './pages/Orgs'` and add
`<Route path="/orgs/:orgId" element={<OrgProfile />} />` inside `AppShell`'s `<Routes>`, so it is
protected for free. The catch-all `<Route path="*" ...>` must stay last.

**Nav (`Layout.tsx`).** `NAV` is a static `Record<Role, NavItem[]>` read once, with no data-derived
entry anywhere in the file — this is a new shape. Derive the organiser list with a `useMemo` over
`NAV[role]` plus a conditional **Organisation profile** entry, rendered **iff**
`manageableOrgIds.length >= 1` and linking to `manageableOrgIds[0]`. Keep the `NavItem` interface
and the `<Icon d={...} />` convention. Do not add a new static `Role` key.
  </action>
