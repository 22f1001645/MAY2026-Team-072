<objective>
Ship ORG-03: the brand kit's validation rules, its upsert endpoint, and the read contract Phase 5
consumes.

Purpose: the `brand_kits` table already exists with JSON columns, so this plan is validation and
seam work rather than schema work. Two things make it load-bearing rather than routine. First,
SQLite and Postgres enforce nothing inside a JSON column, so every shape rule is service-tier and
every rule is the only thing standing between a typo and a Phase 5 template. Second, **nothing
upstream defines the read contract** ROADMAP criterion 3's "readable by the campaign creator"
refers to — Phase 4 must publish that seam, and it is ORG-03's real deliverable.

Output: `BrandKitSchema`, `GET`/`PUT /orgs/<org_id>/brand-kit`, and `brand_kit_for(org)` with its
totality test.
</objective>

  <action>
Add the brand kit's validation and its two endpoints.

**Schema (`backend/app/schemas/__init__.py`).** `BrandKitSchema` with:
`voice_tone = fields.Str(allow_none=True, validate=validate.Length(max=500))`;
`palette = fields.List(fields.Str(validate=validate.Regexp(r"^#[0-9a-fA-F]{6}$")), validate=validate.Length(max=6))`;
`sample_phrases = fields.List(fields.Str(validate=validate.Length(min=1, max=200)), validate=validate.Length(max=10))`;
`source = fields.Str(load_default=BRAND_KIT_MANUAL, validate=validate.OneOf(BRAND_KIT_SOURCES))`
— `BRAND_KIT_SOURCES` imported into the existing constants import block, never restated.

The palette regex is a stored-XSS gate, not a formatting preference. CAMPAIGN-02 interpolates
these strings into generated mail HTML, almost certainly into a `style` attribute, so a free-text
colour is a CSS-context injection. Six hex digits only: no `rgb()` form, no named colours, no
three-digit shorthand.

`source` is client-supplied provenance metadata, not an authorization input — a client that lies
about it changes nothing that matters — so defaulting it and validating the enum is the whole
treatment.

**Service — `upsert_brand_kit(org, data, actor)`.** Follow the `settings_service` singleton
shape, but reach through `org.brand_kit` (the `uselist=False` backref) rather than a
`filter_by(org_id=...)` query — the guard already loaded the org onto `g.org`. Create the row if
it is absent, assign the fields if it is present. Normalise every palette entry with `.lower()`
before storing, so what is stored matches the lowercase the UI renders and a user does not see a
value change on the next reload. Strip phrases and drop empty ones; drop empty palette entries.
Write `AuditRepository.record("organisation", org.id, "Updated organisation brand kit", actor)`
before the single `db.session.commit()`.

**Service — `get_brand_kit(org)`.** Return the read payload with `has_kit` set from
`org.brand_kit is not None`, plus
`ai_available = bool(current_app.config.get("GEMINI_API_KEY"))`. **This read must not create a
row.** An org with no kit gets a truthful "nobody has written one yet", not a freshly-minted
empty row and not a 404 — the campaign creator needs a stable read contract, and a 404 would
force every caller to branch on absence.

`ai_available` lives here and **not** on `/auth/me`: that payload is AUTH-02's authorization
capability contract, and mixing a server feature flag into it invites the next config flag onto
the auth payload too (D-04).

**Controller.** `GET` and `PUT` on `/orgs/<org_id>/brand-kit`, both `@can_manage_org_required`
(P-09 — this surface is never served to a non-manager), schema-load then service then
`jsonify(...), 200`. The parameter is `org_id`.

**`PUT` is the only writer of a `BrandKit` row.** 04-05 adds a draft endpoint that must not
become a second one; note that in this function's docstring so the constraint is visible at the
site someone would be tempted to reuse.

**Tests.** Add to `backend/tests/test_org_profile_brand_kit.py`, named so the `04-VALIDATION.md`
selectors resolve: `brand_kit_roundtrip`, `brand_kit_upsert`, `palette_hex_only`,
`brand_kit_bounds`, `brand_kit_source_enum`, `brand_kit_cross_org`, `ai_available_flag`, plus a
never-saved-kit read test asserting `has_kit is False` and `BrandKit.query.count()` unchanged.

| brand kit → Phase 5 mail template | Every stored value is a future template input; the storage-time rule is the only gate before it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-26 | Tampering | palette entry → CSS context in a Phase 5 mail template | high | mitigate | `validate.Regexp(r"^#[0-9a-fA-F]{6}$")` on every entry, lowercased before storage. No `rgb()`, no named colours, no shorthand. Asserted by `palette_hex_only`. |
| T-04-27 | Denial of Service | unbounded JSON columns | medium | mitigate | Length caps on every field: voice/tone 500, palette 6, phrases 10 × 200. SQLite and Postgres enforce nothing inside a JSON column, so these are the only bounds that exist. |
| T-04-28 | Information Disclosure | brand kit served to a non-manager | medium | mitigate | `can_manage_org_required` on both brand-kit routes; asserted on GET **and** PUT by `brand_kit_cross_org` (P-09). |
| T-04-29 | Elevation of Privilege | client-supplied `source` treated as authority | low | accept | `source` is provenance metadata, never an authorization input. A client that lies about it changes nothing that matters. The enum is still validated so a Phase 5 reader can rely on the value set. |
| T-04-30 | Repudiation | brand-kit mutation | medium | mitigate | One `AuditLog` row per successful save, recorded in the same transaction. |
| T-04-31 | Denial of Service | read-side row creation | low | mitigate | `get_brand_kit` and `brand_kit_for` never write. Asserted by a count-unchanged check across a GET. |
