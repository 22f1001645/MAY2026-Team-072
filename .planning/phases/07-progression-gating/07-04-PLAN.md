<objective>
Make the fest gate legible before the user hits it. The Regional Fest scale card reads its lock state from the server, names which half of the track record is missing and in which city, and the collaborating-orgs step counts named organisations against the server's threshold. When the server still refuses, the existing error block explains it in the server's own words.

Purpose: ROADMAP criterion #1 says a locked option must show an explicit "1 of 2 completed" style explanation "rather than a bare disabled control". That is the whole difference between a gate and a bug report.

Output: an in-place modification of the existing scale-card map, the existing collaborator caption and the existing error-heading map. No new component file — only `regional_fest` can ever be locked, and a `<ScaleOption>` abstraction with one locked product is an interface for one implementation.

Decisions implemented here:
- D-04: the `regional_fest` card gets the live-fetch lock state — a lock affordance plus a "1 of 2 completed" caption, unclickable until the server reports the org eligible for that specific org+city pair.
- D-01: the collaborator counter shows the **named** count with the line "Each Secretary must accept before an admin can approve." — the only place the proposer learns that naming is not accepting before they reach the admin queue.
- D-03: the caption interpolates the selected city into every line, because eligibility is per city and a caption that omitted it would be describing a rule the user cannot locate.
</objective>
