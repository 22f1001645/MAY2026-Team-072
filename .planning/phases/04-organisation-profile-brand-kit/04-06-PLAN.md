<objective>
Build the frontend data layer for Phase 4: the URL-safety helper, the domain types, the adapters
and endpoints, and the query hooks.

Purpose: every Phase 4 surface reads through this layer, and three of its rules are load-bearing
rather than plumbing — `safeExternalHref` is the third layer of ORG-02's defence, the `JSON.parse`
guard turns this phase's single most predictable rejection (a 413 on an oversized logo) from an
unhandled exception into a readable message, and the adapter is the only place a served logo path
becomes an absolute URL.

This plan runs in **parallel with the backend's ORG-02 work**: it shares no files with any backend
plan and builds against the endpoint contract already fixed by `04-RESEARCH.md` §D-1 and
`04-UI-SPEC.md`. Its own tests are self-contained; the integration proof lands in 04-07 through 04-09.

Output: `safeExternalHref`, the Phase 4 types, `adaptOrgProfile`/`adaptBrandKit`, the eight
endpoint wrappers and the query hooks.
</objective>

    - `safeExternalHref('//evil.com/x')` → `undefined` (scheme-relative)
    - `safeExternalHref('/relative/path')` → `undefined`

    - A malformed string that makes `new URL()` throw → `undefined`, never a thrown error

  <action>
Add `safeExternalHref(url?: string | null): string | undefined` to `frontend/src/lib/format.ts`,
exported as a named `export function` beside `cx`.

Parse with the platform's own `new URL(...)` inside a `try/catch`, returning `undefined` on any
throw. Accept only when `parsed.protocol` is exactly `'http:'` or `'https:'` (the `URL` API
lowercases the protocol, so no manual casing is needed). Return the **original** string on
acceptance, not `parsed.href` — the server already normalised what it stored, and re-serialising
client-side would display something different from what was saved.

href but does not block it, so React is not the security boundary here. Returning `undefined`
makes React omit the attribute entirely, and the element renders as inert text. This is layer 3;
layer 1 is the server write gate and layer 2 is the server read filter.

Create `frontend/src/lib/__tests__/url-safety.test.ts` as a vitest table over every case in
`<behavior>`, following the docblock-then-imports shape of `view-not-sent.test.ts`. Write the
table first and watch it fail before implementing.

**`api.ts` — two fixes to the shared `request` helper, both required before any Phase 4 surface
works.**

First, **guard the JSON parse**. Wrap `JSON.parse(text)` in `try { ... } catch { body = null }`.
The `body?.` chains below already tolerate `null`, so this is a one-change fix. Flask's
`MAX_CONTENT_LENGTH` 413 and any proxy or dev-server HTML error page currently throw a raw
`SyntaxError` that is not an `ApiError`, so the 401 branch is never reached and the page renders
its generic fallback with a parser error beneath it. This is 04-UI-SPEC.md contract addition 4 and
it turns this phase's most predictable rejection into a readable message.

Second, **do not send a JSON content type with a FormData body**. The header object hardcodes
`'Content-Type': 'application/json'`, and an explicit `undefined` in an object literal does not
delete a key. Add an explicit `delete headers['Content-Type']` when `options.body instanceof FormData`,
so the browser sets the multipart boundary itself.

**Adapters.** Add `adaptOrgProfile` and `adaptBrandKit` beside `adaptMe`, under the existing
comment stating this module is the only place snake_case is allowed. `adaptOrgProfile` is also
where the logo path becomes absolute: `logo_url` arrives as `/api/v1/uploads/<uuid>.<ext>` and is
resolved against `BASE` here, **exactly once**. No component concatenates a base URL — that is the
same "the adapter is the only place" rule the file already states for casing. A null `logo_url`
stays null.

**Endpoints.** Add wrappers for the seven org-scoped calls, camelCase in and snake_case on the
wire, each with the short docblock the file's existing entries carry:
`orgProfile(orgId)` → `GET /orgs/{id}/profile`;
`updateOrgProfile(orgId, payload)` → `PATCH` (payload may carry `bio` and an explicit
`logo_url: null` to clear the logo — there is no delete endpoint);
`replaceSocialLinks(orgId, payload)` → `PUT /orgs/{id}/social-links`;
`uploadOrgLogo(orgId, file)` → `POST /orgs/{id}/logo` with a `FormData` body;
`brandKit(orgId)` → `GET /orgs/{id}/brand-kit`;
`saveBrandKit(orgId, payload)` → `PUT`;
`draftBrandKit(orgId, signal)` → `POST /orgs/{id}/brand-kit/draft`, accepting an `AbortSignal` so
04-09 can implement its 30-second client abort.

Opportunistically type `orgs()` as `Promise<Organisation[]>` rather than `Promise<any[]>` while
extending the interface it returns — it is the same line and leaving it `any` would defeat the new
type immediately. Change nothing else in that region.

**No capability value is ever added to a request** — no header, no query parameter, no body field
(P-10). `manageableOrgIds` decides what renders; `can_manage_org` decides what is permitted.

  <action>
Add the Phase 4 hooks, copying the existing query/mutation/invalidation shapes exactly.

`useOrgProfile(orgId?: string)` → `useQuery({ queryKey: ['orgProfile', orgId], queryFn: () => api.orgProfile(orgId!), enabled: !!orgId })`.

`useBrandKit(orgId?: string, canEdit?: boolean)` → the same shape with
**`enabled: !!orgId && !!canEdit`**. This gate is 04-UI-SPEC.md S6's visibility rule expressed in
one expression: `GET /orgs/<id>/brand-kit` is `can_manage_org_required`, so a non-manager would get
a 403, and the page must never issue the request rather than issuing it and swallowing the error.
A brand kit is an internal working document for an organisation's own communications, not part of
its public identity, so rendering an empty or errored card would advertise a surface the reader can
never use.

Mutations — `useUpdateOrgProfile`, `useReplaceSocialLinks`, `useUploadOrgLogo`, `useSaveBrandKit` —
each following `useUpdateEvent`: a `mutationFn` taking `{ id, payload }`, and `onSuccess`
invalidating `['orgProfile', id]` (plus `['brandKit', id]` for the brand-kit save) and `['orgs']`,
because `/admin/orgs` renders logos from the same rows and would otherwise show a stale one.

`useDraftBrandKit` is a `useMutation` with **no** `onSuccess` invalidation — the draft persists
nothing, so there is no server state to refresh. Invalidating here would refetch the saved kit and
overwrite the draft in the form, which is the exact opposite of criterion 4's behaviour. Pass the
`AbortSignal` through to `api.draftBrandKit`.

Add `placeholderData: keepPreviousData` to `useCapabilities` (the symbol is already imported at the
top of the file). Without it a background `/auth/me` refetch drops the capability snapshot for a
frame and every Edit control on the page blinks out and back — 04-UI-SPEC.md S2's rule.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Flask API → browser DOM | Server-vouched URLs still reach an `href` sink; the client applies a third check rather than assuming the first two held. |
| server config → client bundle | Anything named `VITE_*` is inlined into the shipped bundle and is public. |
| client capability state → server | A rendering hint must not become an authorization claim. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-04-41 | Tampering | user-supplied URL in an `href` | high | mitigate | `safeExternalHref` returns `undefined` for any non-`http(s)` scheme so React omits the attribute. React 18.3.1 only warns on `javascript:`; a dev-mode console warning is not a mitigation. |
