filter alone discharges. It is the control most likely to be dropped as "redundant". It is not.

order instagram, linkedin, x, youtube, facebook, github). Declaring it here means the seven-row
editor cannot drift from the server. `website` appears in `SOCIAL_FIELD_ORDER` and **must not**

**`backend/app/url_safety.py`** — a module docstring naming ORG-02 and stating the one-function-two-call-sites
rule. `ALLOWED_SCHEMES = ("http", "https")` and `MAX_SOCIAL_URL_LENGTH = 300` (this must be ≤
`OrganisationSocialLink.url`'s `String(300)` or SQLite silently accepts what Postgres rejects).

`normalise_social_url(raw, platform) -> str | None` performs, **in this order**:
length/empty guard → platform lookup in `SOCIAL_PLATFORMS` → `urlsplit(raw.strip())` →
**scheme check first and unconditionally** (`p.scheme.lower() not in ALLOWED_SCHEMES` → reject;
marshmallow's own check is conditional on `"://" in value` and must not be relied on for this) →
reject if `p.username` or `p.password` → reject if `p.port is not None` → read the host from
**`p.hostname`**, never `p.netloc` → reject a falsy host → reject if `host.encode("ascii")`
raises → reject IP-literals and localhost and private/loopback/link-local ranges via
`ipaddress.ip_address` on the host (catching `ValueError` for a normal domain name) plus an
explicit `localhost` check → host allowlist using the rule `host == a or host.endswith("." + a)`
(the leading dot is the whole defence against `instagram.com.evil.com`) → re-serialise with
`urlunsplit((scheme_lower, host, p.path, p.query, ""))`, dropping the fragment → final length
check on the normalised value.

Return the **re-serialised** string, never `raw`. `urlsplit` strips `\t\r\n` before parsing
(`urllib.parse._UNSAFE_URL_BYTES_TO_REMOVE`), so storing `raw` would persist a string that is
not the string that was validated.

`is_renderable_social_url(url, platform) -> bool` is `normalise_social_url(url, platform) is not None`.

`normalise_website_url(raw) -> str | None` (option-a only) shares every step above **except** the
platform lookup and the host allowlist. Factor the shared steps into one private helper so the
two entry points cannot drift — the narrowing must be visible as one skipped check, not a second
parser.

Do **not** hand-roll URL parsing. Do not `str.split("://")`. Reusing the same parser the runtime
uses is the entire defence; every verified bypass above is a parser differential.

  <action>
Add the write endpoint, the read-side filter, and the two UI-SPEC contract additions.

**Schemas.** `SocialLinkSchema` with
`platform = fields.Str(required=True, validate=validate.OneOf(SOCIAL_PLATFORM_KEYS))` — imported
from constants, never restated (Pitfall 7; `OrgSchema` at `schemas/__init__.py:119` is the
counter-example already in the file) — and `url = fields.Str(required=True, validate=[validate.Length(max=300), validate.URL(schemes={"http","https"})])`.
Pass `schemes` explicitly: marshmallow 3.22.0's default set includes `ftp` and `ftps`.
`SocialLinksReplaceSchema` carries `links = fields.List(fields.Nested(SocialLinkSchema))` and,
under option-a, `website = fields.Str(allow_none=True, validate=validate.Length(max=300))`.
Marshmallow is the cheap first pass producing a 422; `normalise_social_url` produces the
**domain** rejection as a 400 with a specific code. Both surface through the existing envelope.

**Service — `replace_social_links(org, data, actor)`.** De-duplicate platforms **in the payload
first**, before touching the database, raising
`ApiError("...", "duplicate_platform", 400, {"platform": <key>})` — an `IntegrityError` is not a
user-facing message. Then normalise every URL through `normalise_social_url`, raising
`ApiError(<message>, "social_url_scheme"|"social_url_host", 400, {"platform": <key>})`. The two
codes must be distinguishable: a rejected scheme and a rejected host are different user
corrections and UI-SPEC S4 maps them to different headings. For the website field raise the same
codes with `details = {"field": "website"}`. **`details` must be a non-empty dict** or
`errors.envelope()` drops it and the UI cannot place the error on a row.

Then, inside one transaction: delete every existing `OrganisationSocialLink` for the org,
`db.session.flush()`, then insert the new rows, then `AuditRepository.record("organisation", org.id, "Replaced organisation social links", actor)`, then one `db.session.commit()`. The
`flush()` between delete and insert is what prevents `uq_org_social_platform` firing when a user
edits an existing platform's URL. A blank URL for a platform means "remove that link" — omit the
row rather than storing an empty string.

**Service — the read-side filter in `public_profile(org)`.** Build the returned `social_links`
list as only those rows where `is_renderable_social_url(row.url, row.platform)` is true, and
build `withheld_platforms` as the sorted platform keys of the rows that failed. This filter is
ROADMAP criterion 2's second clause. Rows can pre-date Phase 4, arrive from a direct database
edit or seed data, or come from a future bug; the model's own docstring says the column is
"stored unvalidated by this layer on purpose". Without this filter, criterion 2 is a claim about
the write path, not a property of the system. **Do not put it in `to_dict()`** — a `to_dict()`
cannot omit itself from a list. `OrganisationSocialLink.to_dict()` stays dumb and unchanged.

Order the returned links by `SOCIAL_FIELD_ORDER` so the seven-row editor maps each platform to a
stable row.

`withheld_platforms` carries **keys only** — never the URL, never a reason (P-05a).

**Controller.** `@org_profile_bp.put("/orgs/<org_id>/social-links")` with
`@can_manage_org_required`, schema-load then service then `jsonify(...), 200`. The param is
`org_id`. Return the same payload shape `GET /profile` returns, so the client re-renders from

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Flask API | A POR holder supplies arbitrary URL strings for their own organisation. |
| database → Flask API → browser | Rows already in `organisation_social_links` are untrusted regardless of how they arrived. |
| Flask API → any future outbound fetcher | A stored URL is a latent SSRF target if anything ever fetches it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-07 | Tampering | stored social URL → browser href | high | mitigate | Unconditional `http`/`https` scheme allowlist checked **first** via `urlsplit().scheme`, before any host logic; `javascript://instagram.com/%0aalert(1)` is the test row proving order matters. |
| T-04-08 | Spoofing | host allowlist | high | mitigate | Allowlist on `.hostname`, never `.netloc`; rule is `host == a or host.endswith("." + a)`. Test rows: `https://instagram.com@evil.com/x` and `https://instagram.com.evil.com/x`. |
| T-04-09 | Spoofing | IDN homograph | medium | mitigate | Reject any hostname failing `.encode("ascii")`. Test rows: `ínstagram.com`, `instagram。com`. |
| T-04-10 | Tampering | parser differential | high | mitigate | Store the re-serialised `urlunsplit` output, never `raw`. `urlsplit` strips `\t\r\n` before parsing, so validating raw and storing raw persists a different string than the one validated. |
| T-04-11 | Information Disclosure | SSRF via a stored URL | medium | mitigate | Reject IP-literals, `localhost`, and private/loopback/link-local ranges at save time, so no stored value is ever an internal target even though nothing fetches these today. |
