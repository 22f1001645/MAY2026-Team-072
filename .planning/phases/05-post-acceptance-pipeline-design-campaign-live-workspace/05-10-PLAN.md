**`campaign_service.save_poster(activity, file_storage, actor)`:**
1. `assert_editable(activity)` — a live campaign's poster is frozen with everything else.
2. Read the leading bytes and decide the type from **magic bytes**, not from
   `file_storage.mimetype` or the filename: PNG (`\x89PNG\r\n\x1a\n`), JPEG (`\xff\xd8\xff`),
   WebP (`RIFF` … `WEBP`). Anything else — including SVG, which is XML that a browser will
   execute if served from the API origin — raises
   `ApiError("Only PNG, JPG or WebP images are accepted.", "unsupported_media_type", 415)`.
   The multipart part's `Content-Type` is entirely client-controlled and `secure_filename()`
   can return an empty string, so neither is a type decision.
3. Build the stored name as `f"{uuid4().hex}{ext}"` with `ext` derived from the sniffed type.
   Never echo or derive from the client's filename.
4. Write into Phase 4's `upload_dir()`. Do not compose a path with `os.path.join` and do not
   resolve the directory independently — 04-03 owns that helper and forbids the former.
5. `campaign = _get_or_create_campaign(activity)`; set `poster_name`; commit; return
   `{"poster_name": ...}`. Last-write-wins falls out of the singleton accessor, which is what
   AC-13 asserts.

file into memory to measure it — `MAX_CONTENT_LENGTH` rejects an oversize body with a 413

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser multipart body → Flask | Attacker-controlled bytes, filename and Content-Type all cross here together |
| Flask → `backend/instance/uploads/` | The only place this application writes to the filesystem |
| `GET /api/v1/uploads/<name>` → any browser | A deliberately public serve route on the API origin |

## STRIDE Threat Register (ASVS L1, block on high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-48 | Tampering | stored XSS via an uploaded SVG served from the API origin | critical | mitigate | Type decided from sniffed magic bytes restricted to PNG/JPEG/WebP; SVG is rejected with 415 before any write. Asserted by `test_poster_upload_rejects_svg`, which sends SVG bytes under a `.png` name and an `image/png` content type |
| T-05-49 | Tampering | client filename injection into the stored path | high | mitigate | The stored name is `uuid4().hex` plus a sniffed extension; the client filename is never echoed, never joined, never stored |
| T-05-50 | Information Disclosure | path traversal on the serve route | high | mitigate | Phase 4's route uses `send_from_directory`, which routes through `safe_join`; Phase 5 adds no serve route and no `os.path.join` |
| T-05-51 | Denial of Service | memory exhaustion via a huge upload | high | mitigate | `MAX_CONTENT_LENGTH` rejects before the body is buffered; no per-view `len(file.read())` anywhere. Asserted by the 413 test |
| T-05-52 | Denial of Service | the raised 5 MB app cap widening the logo endpoint's exposure | medium | mitigate | `LOGO_MAX_BYTES` keeps the 2 MB bound as a per-endpoint check on Phase 4's logo path, so raising the shared key does not relax the logo rule (OD-2) |
| T-05-53 | Tampering | poster replacement on a published campaign | high | mitigate | `assert_editable` is the first call in `save_poster`; asserted by `test_poster_upload_blocked_when_live` |
| T-05-54 | Elevation of Privilege | uploading a poster to another activity's campaign | high | mitigate | `@can_manage_activity_required` resolves the activity from the URL id and 403s on predicate failure |
| T-05-SC | Tampering | package-manager installs | high | accept | This plan runs no `pip install` / `npm install`. It consumes Phase 4's already-audited upload primitive and adds no dependency |
</threat_model>
