# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** the seven UI surfaces Phase 2 touches (see `## Surface Contracts`). Everything else in `frontend/` is inherited and out of scope.

**Governing principle for this phase:** every token, class string and primitive named below already exists in the codebase unless explicitly marked `NEW`. This is a brownfield design system derived from the EKATVA Brand Kit v1.0; this phase extends it and introduces exactly two new primitives.

### shadcn Gate Outcome

`components.json` is **not present** and is **deliberately not introduced**.

Rationale (recorded so this is not re-litigated in Phase 3–8):
1. `PROJECT.md` carries a standing "no new frameworks" constraint.
2. `tailwind.config.js` already encodes a complete, brand-kit-traced token set (colors, type ramp, shadows, easing, keyframes) that shadcn's CSS-variable theming would shadow rather than extend.
3. Eight primitives (`Button`, `Card`, `Badge`, `Input`, `SectionTitle`, `StatCard`, `Progress`, `EmptyState`) plus `Loading` / `ErrorState` / `ToastProvider` are already in use across 18 pages. Introducing a parallel primitive set mid-milestone creates two ways to render every control.

**Consequence:** `## Registry Safety` is not applicable. No registry, no third-party blocks, no `shadcn view` gate required.

## Spacing Scale

Base unit 4px. Declared values (all multiples of 4):

| Token | Value | Tailwind | Usage in this phase |
|-------|-------|----------|---------------------|
| xs | 4px | `p-1`, `gap-1` | switcher track inner padding; icon-to-label gap in badges |
| sm | 8px | `gap-2`, `mt-2` | gap between dialog action buttons; icon-to-text in the banner strip |
| md | 12px | `px-3`, `gap-3`, `mb-3` | sidebar rail horizontal padding (matches `nav` `px-3`); banner icon-to-content gap; switcher segment horizontal padding |
| lg | 16px | `px-4`, `gap-4`, `mb-4` | banner internal horizontal padding; dialog field stack gap |
| xl | 24px | `px-6`, `py-6`, `mb-6` | dialog panel padding; banner bottom margin above `SectionTitle` |
| 2xl | 32px | `mb-8` | separation between the banner block and the first stat grid |
| 3xl | 48px | `py-12` | empty-state vertical padding (inherited from `EmptyState`) |

**Vertical rhythm rules for this phase:**
- The switcher sits **12px** below the sidebar wordmark block and **12px** above the first `NavLink` (`my-3` on the switcher wrapper). It must not touch either.
- The banner carries `mb-6` (24px) and never `mb-4` — 24px is what separates it from the page title clearly enough to read as a separate object.
- Dialog: `p-6` panel, `gap-4` between fields, `mt-6` before the action row.

**Exceptions (documented, not to be "fixed") — NOT part of the declared scale above.**

> ⚠️ The values in this table are **not tokens and not available for any new spacing decision in this phase.** Each is valid only on the one inherited primitive named in its row. Every new spacing decision — new component, new gap, new margin, new padding — must come from the declared scale table above (4 / 8 / 12 / 16 / 24 / 32 / 48). If a value below looks useful somewhere else, that is a misread: use the nearest declared token instead.

| Exception | Value | Valid ONLY on | Reason |
|-----------|-------|---------------|--------|
| `Button` vertical padding | 6px (`py-1.5` sm), 10px (`py-2.5` md), 14px (`py-3.5` lg) | the existing `Button` primitive in `ui.tsx` — nothing else | Hardcoded in the existing `Button` base. Changing it re-flows every page in the app. Inherited, not introduced. |
| `Select` / `Input` vertical padding | 10–12px (`py-2.5`, `py-3`) | the existing `Input` primitive and the lifted `selectCls` string — nothing else | Same — inherited from existing form controls. |
| Switcher segment vertical padding | 6px (`py-1.5`) | the two `ViewSwitcher` segments — nothing else | Must match `Button size="sm"` so the switcher and the banner's action buttons read as the same control family. |
| Icon-only button box | 36px (`h-9 w-9`) | the existing header notification button and sidebar identity block — nothing else | Matches the existing header notification button and identity block. 36px exceeds WCAG 2.5.8 AA (24px minimum target). No new icon-only controls smaller than this. |

## Typography

Four declared sizes for the surfaces this phase builds. All are existing `tailwind.config.js` tokens except the 14px control size, which is the established arbitrary value throughout `Layout.tsx`.

| Role | Size | Weight | Line Height | Token | Applied to |
|------|------|--------|-------------|-------|-----------|
| Heading | 20px | 600 | 1.4 | `text-h3` | dialog titles, empty-state heading, boot-failure heading |
| Body | 16px | 400 | 1.6 | `text-body` | banner body copy, error messages, the "no effect on access" reassurance line |
| Control | 14px | 500 (600 when active/selected) | 1.4 | `text-[14px]` | nav items, switcher segments, banner title, select values, button labels (`Button size="md"`) |
| Caption | 12px | 600, `uppercase tracking-wider` | 1.5 | `text-caption` | field labels, eyebrows, audit-log note, "Overridden {date}" |

**Weights — exactly two declared:** `400` (regular) and `600` (semibold).

**Weight exception (inherited, not introduced):** the existing `Button` base hardcodes `font-bold` (700) and `SectionTitle` renders its `h1` at `font-bold`. Both are pre-existing brand-kit decisions. **This phase introduces zero new 700-weight text** — any new heading, label or body string uses 400 or 600.

**Page titles** on surfaces this phase touches are rendered by the existing `SectionTitle` primitive (36px / 700 / 1.2, `text-h1`, `text-gold`). It is inherited wholesale and therefore not part of the declared ramp above.

**Casing rules:**
- `uppercase tracking-wider` is reserved for 12px captions and eyebrows only. Never on 14px or larger.
- Switcher segment labels are sentence case: `Student`, `Organiser`. Never uppercase — the existing `Button` uppercase treatment would make them read as CTAs rather than as a state indicator.

## Color

Dark surface only. Percentages are share of painted pixels on a dashboard route.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(0.13 0.015 175)` — Oneness Black, ~`#030907` (`bg-onyx`) | page background, main column, sticky header at `bg-onyx/80` + `backdrop-blur-xl`, dialog panel |
| Secondary (30%) | `#1F4F59 → #0E2F36` (`bg-brand-gradient`) for the sidebar; `from-white/[0.04] to-white/[0.01]` + `border-white/5` (`Card`) for surfaces; `bg-black/20` for inset wells | sidebar, cards, the switcher track, the sidebar identity well |
| Accent (10%) | `#5CE6C9` — Ekatva Teal (`teal`) | see reserved list below |
| Accent–warm (inside the same 10% budget) | `#FFCF96` — Unity Gold (`gold`) | headings only, plus the academic-status banner surface (`bg-gold/[0.06]`, `border-gold/25`) and its icon |
| Destructive | `red-300` text on `border-red-400/40` with transparent fill (existing `Button variant="danger"`); `red-400/10` fill for `Badge tone="danger"` | sign-out hover state and the "Withdrawn" status chip only |

**Teal accent is reserved for exactly these elements:**
1. The active `NavLink` (`bg-teal/12 text-teal shadow-[inset_2px_0_0_#5CE6C9]`)
2. The **active** segment of the view switcher (same `bg-teal/12 text-teal` language, plus a `0 0 0 1px rgba(92,230,201,0.35)` inset ring)
3. Primary CTAs: "Confirm status", "Save override", "Sign in", "Try again"
4. Focus rings — `focus-visible:ring-2 focus-visible:ring-teal/50` on every interactive element in this phase, without exception
5. The `Mandala` mark during session resolution
6. Inline text links

**Teal is explicitly forbidden on:**
- the academic-status banner surface, border or icon (gold — a nudge, not an action)
- the **inactive** switcher segment (`text-graytext-light`)
- any disabled control, in either the unauthorised or the busy variant
- decorative dividers, card borders, or section rules

**Gold budget:** gold already carries every `h1`/`h2` in the app. The banner is the only *surface* this phase paints gold. No second gold surface may be added in Phase 2.

**Contrast floors (AA, verified against `#030907` / the card gradient):**
- `text-offwhite` `#F8F8F8` — primary text
- `text-graytext-light` `#AAAAAA` — secondary text, ≥14px only. **Never** on 12px captions carrying required information.
- `text-graytext-mid` `#666666` — decorative and tertiary only (footer, hints). **Never** the sole carrier of a state, a label, or an instruction.
- `text-teal` `#5CE6C9` and `text-gold` `#FFCF96` both clear 4.5:1 on `bg-onyx`.

**Never encode state in color alone.** Every state distinction in this phase carries a second channel — the active switcher segment carries a ring plus `aria-checked`; the banner carries an icon plus a heading; a disabled-unauthorised control carries a padlock plus a sentence.

### Primary visual anchor (composed dashboard route)

**The `SectionTitle` is the primary anchor** — at 36px/700 gold it is the largest, warmest and highest-contrast element on the route, and it is what the eye lands on first even though the banner sits above it in document flow. Rank order is: **(1) `SectionTitle` → (2) academic-status banner → (3) view switcher.** The banner is deliberately second — 14px title on a 6%-alpha gold surface, read *on the way to* the title rather than instead of it, because it is a nudge the user did not ask for. The switcher is third by placement, not by styling: it lives in the sidebar rail and competes only with nav items, never with main-column content.

**Enforceable consequence:** if the banner ever out-shouts the title in review, the fix is to quiet the banner (lower alpha, drop the icon), **never** to enlarge or re-weight `SectionTitle` — which is inherited and shared by 18 pages.

| Slow-boot label (>600ms) | **Restoring your session…** |
| Confirm success toast | **Academic status confirmed** (`type: 'success'`) |
| Override success toast | **Academic status updated for {Name}** (`type: 'success'`) |
| Sign-out toast | **Signed out on this device.** — the copy states D-04's device scope so the user is never left guessing about other devices |
| Banner title | **Confirm your academic status for this term** |
| Banner body | **It takes a moment and keeps your community profile accurate.** |
| Access-decoupling reassurance (in the dialog, always visible) | **This only affects how we describe you in the community. It never changes what you can access.** |
| Admin override note (in the dialog, always visible) | **Recorded in the audit log as an override by you. {Name} can still update this themselves.** |
| Unauthorised-control explanation pattern | **Only {the role} can do this.** — always names who *can*, never says "you can't" |
| Destructive confirmation | **None. This phase ships zero destructive actions.** Sign out is deliberately one-click with no confirm dialog — the cost of an accidental sign-out is one sign-in, and a confirm on every logout is a friction tax paid on every correct use. The toast above replaces the confirmation. Selecting **Withdrawn** is self-declared, reversible, and changes zero access, so it gets no confirmation either. |

### Reasoned exception: bare "Cancel" as the dialog dismiss (inherited, not introduced)

Every *primary* CTA in the table above is scoped to its object — **Confirm status**, **Save override** (not "Save"), **Go to sign-in**. The dismiss action in S5 and S6 deliberately does **not** follow that rule, for the same reason the `Button` 6/10/14px paddings and the `font-bold` heading weight are left alone: **it is an existing app-wide convention, and this phase's job is not to fork it.**

The convention already in the codebase, verified 2026-08-10:

| Existing call site | Label | Role |
|--------------------|-------|------|
| `pages/Orgs.tsx:408` (deactivate confirm) | `Cancel` | dismiss |
| `pages/Orgs.tsx:608` (seed modal) | `Cancel` | dismiss |
| `pages/Orgs.tsx:740` (POR modal) | `Cancel` | dismiss |
| `pages/Orgs.tsx:775` (add-city modal) | `Cancel` | dismiss |
| `pages/Expenses.tsx:127` (inline add form) | `Cancel` | dismiss |
| `pages/ProposalNew.tsx:236` | `Cancel` | dismiss |
| `pages/EventDetail.tsx:155` | `Cancel registration` | **the action itself** |

Six of seven render bare `Cancel` as `Button variant="ghost"` for "close this without writing anything". The seventh scopes the word precisely because there "cancel" is the *verb being performed*, not the escape hatch. That is the rule, and it is already consistent:

> **Bare `Cancel` = abandon this dialog, nothing was written.**
> **Scoped `Cancel {noun}` = cancelling the noun *is* the destructive action.**

S6 lands on `/admin/orgs`, the very file carrying four of the six existing bare-`Cancel` buttons. Introducing **Cancel override** there would put two different dismiss vocabularies in one screen and — worse — would read as "cancel the existing override", i.e. as an action that writes something. **Cancel override** is therefore rejected as actively misleading, not merely inconsistent.

**Locked:** S5 and S6 both use bare **Cancel**. Neither uses **Close** — equally generic, and unattested as a button label anywhere in `frontend/src` (the one existing drawer dismisses via a bare `✕` glyph at `EventAnnouncementsModal.tsx:53`, which is exactly the unlabelled pattern S4 already rejects). Neither uses a scoped variant. If a future phase adds a dialog whose dismiss genuinely discards user work, that dialog — not this convention — is what changes.

### S2 — Cold-load / session resolution (D-08)

| Property | Contract |
|----------|----------|
| Window | From app mount until `/auth/refresh` → `/auth/me` resolves. The public/protected route split is gated on it. |
| 0–600ms | **Reuse the existing `App.tsx` boot state verbatim:** `<div className="grid min-h-screen place-items-center bg-onyx">` wrapping `<Mandala size={48} className="animate-spin-slow" />`. No skeleton, no spinner, no progress bar, no text. The fast path must not flash a message. |
| >600ms | Fade in `Restoring your session…` beneath the mark, `text-body text-graytext-light`, `animate-fade-up`. The wrapper carries `aria-busy="true"`; the label carries `role="status" aria-live="polite"` so it announces once. |
| >8000ms | Replace the whole viewport with `ErrorState` inside a `grid min-h-screen place-items-center` wrapper, using the "Could not restore your session" copy, plus `Button` **Try again** (re-runs the boot sequence) and `Button variant="ghost"` **Go to sign-in**. |
| 401 from refresh | Render public routes immediately. No error, no toast — an expired cookie on a cold load is the normal state for a returning visitor, not a failure. |
| Partial failure | `/auth/refresh` succeeds but `/auth/me` fails → treat as no session: clear auth, render public routes. There is no half-authenticated render. |
| Never | Never render Landing (or any public route) and then swap to the protected shell. No flash of the wrong app. |

| In-flight form input | Not preserved. Out of scope. The copy above is worded so nothing is promised. |

## Interaction States

The disabled-because-unauthorised vs disabled-because-busy distinction, made explicit. These two must never look alike.

### A — Not permitted (capability absent)

**Default: do not render.** If `manageableActivityIds` does not contain the id, the control is absent from the DOM. A control the user can never enable is noise, and a greyed control advertises the existence of a power they do not have.

**Render-locked exception** — permitted only when (a) removing the control would break a layout the user is reading as a checklist, or (b) the user could plausibly acquire the capability (e.g. a team member who could be made Meetup Head). In that case, and only in that case:

| Channel | Value |
|---------|-------|
| Disabled attributes | `disabled` **and** `aria-disabled="true"` |
| Visual | `opacity-40 cursor-not-allowed` (inherited from `Button`'s disabled base) |
| Marker | A 12px padlock glyph immediately before the label |
| Explanation | A **visible** line beneath the control, `text-caption text-graytext-light`: **Only {the role} can do this.** — plus the same string as `title`. A tooltip alone is not acceptable: it is unreachable on touch. |
| Pointer events | Must stay hoverable and focusable. **Never `pointer-events-none`** — that makes the explanation unreachable by keyboard. |
| Label | Unchanged. Never gains an ellipsis, never gains a spinner. |

### B — Busy (request in flight)

| Channel | Value |
|---------|-------|
| Disabled attributes | `disabled` **and** `aria-busy="true"`. **Never** `aria-disabled` — the control is not unavailable, it is working. |
| Visual | `disabled:opacity-40` from the `Button` base. No padlock. No explanatory line. |
| Label | Swaps to the present-participle form of **its own verb**: "Confirm status" → **Confirming…**, "Save override" → **Saving…**, "Sign in" → **Signing in…**, "Try again" → **Retrying…** |
| Minimum duration | 300ms visible, so a 40ms response does not produce a flicker |
| Scope | Sibling inputs in the same form go `disabled` for the duration; unrelated controls elsewhere on the page do not. |

### The discriminator, stated for the reader

> A **busy** control keeps its own verb and gains an ellipsis.
> An **unauthorised** control keeps its label unchanged, gains a padlock, and gains a sentence naming who *can*.

Never both. A busy control never shows a padlock. An unauthorised control never shows an ellipsis or a spinner. A single control may move from A to B (once permitted, then clicked) but never displays both languages in the same frame.

### C — Blocked by a fixable precondition

Submit controls stay **enabled** when the form is incomplete. Validation fires on submit and points at the offending field (S5's rule). A pre-disabled submit button leaves the user with no way to ask *why*, which is the same dead end as an unexplained lock.

### Focus and motion, globally

- Every interactive element added in this phase carries `focus:outline-none focus-visible:ring-2 focus-visible:ring-teal/50`. No exceptions, including the banner's ghost dismiss.
- All transitions use `duration-200 ease-material` (`cubic-bezier(0.4, 0, 0.2, 1)`).
- `prefers-reduced-motion` is already handled app-wide in `index.css`; no component-level handling is needed or permitted (a second mechanism would drift).
