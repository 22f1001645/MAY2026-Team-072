**Clearing.** **Leave a row blank to remove that link.** as a hint beneath the group. The payload is
replace-all and a blank row is simply omitted; there is no per-row delete button because the field
itself already is one.

**Save.** **Save links** plus a ghost **Cancel** in a `mt-6 flex justify-end gap-2` row. **Save
links stays enabled at all times** — never pre-disabled on a client-side URL check. The server owns
the rule; a greyed button with no explanation is a worse dead end than one round trip, and a client
that pre-validated would be a second, weaker copy of the very validator this phase exists to
centralise.

**Per-field rejection.** Choose the heading from the envelope `code`, **never** by string-matching
the message, using the module-level map + fallback-helper shape from `ProposalNew.tsx`:
`social_url_scheme` → **That link needs to start with http:// or https://**;
`social_url_host` → **That doesn't look like a {Platform} address**;
`duplicate_platform` → **One link per platform**;
`validation_error` → **Check this link**. The body is the server's sentence verbatim, rendered
beneath the offending field at `text-caption`, and the field gains `border-red-400/50`.

Place the message using `error.details` — `{platform: "<key>"}` for a platform row,
`{field: "website"}` for the website field. For a 422, walk marshmallow's nested `details` structure
to the specific row. When a row cannot be resolved, render the message once at section level; never
render a raw serialised object. This is a new shape in this codebase — no page reads `.details`
today — and the section-level render is the documented degraded fallback.

**A rejected save keeps everything.** The payload is replace-all, and a rejection must **never**
clear the form. Every other row keeps its typed value, the website field keeps its value, and only
the offending field is marked. This is the single most important rule on this surface.

**Withheld rows.** The editor is populated from the same filtered payload the read view uses, so a
row the server withheld would otherwise look like it was never saved. Render a withheld row with an
**empty** `Input`, a `Badge tone="warn"` **Hidden** beside its label, and the caption **This link
was saved earlier but is no longer safe to show. Enter it again to restore it.** at
`text-caption text-amber-300`. Amber, not red — the user did nothing wrong. **The withheld URL is
never rendered, never placed in a value, and never reaches the DOM**; `withheld_platforms` carries
keys only.

**Accessibility and focus.** Every interactive element carries
`focus:outline-none focus-visible:ring-2 focus-visible:ring-teal/50`. On a field-level rejection,
focus moves to the first offending field (the message is beside it); on a section-level rejection
the strip is scrolled into view with `block: 'center'`, receives focus via `tabIndex={-1}`, and is
`role="alert"`.

**Spacing.** Use only the declared scale — 4 / 8 / 16 / 24 / 32 / 48. **No `gap-3`, `mb-3`, `mt-3`,
`space-y-3`, `py-3` or `px-3` anywhere.**

  <action>
Build the read render and wire the Links card into the page.

**The absence rule.** A link the server refuses to vouch for is **simply not there**: not
shown-and-disabled, not greyed, not struck through, not replaced by a placeholder, not counted, and
reserving no space. The read view is a faithful picture of what the server vouches for, and nothing
else. **There is no "1 link hidden" string anywhere in this phase** (P-05b).

**Manager parity.** A manager in *read* mode sees precisely what a reader sees, with no extra
marker on the links themselves. The withheld state is disclosed only by the section-header count
badge and only inside the editor. A manager must be able to see the reader's view without a decoder
ring.

**Form.** `flex flex-wrap gap-2`. Each link is an `<a>` styled as a chip using the exact class
string in S5. The label is the **platform display name, never the raw URL** — long URLs overflow
and a URL is not information a reader scans for — and the full normalised URL rides in `title`. The
website chip's label is **the hostname**, derived client-side via `new URL(href).hostname`, which
is safe because the href already passed the server's read filter; `Website` alone is uninformative
and the hostname is what a reader actually checks before clicking. A 14px external-link stroke SVG
follows the label, `aria-hidden`.

**Layer 3.** `href={safeExternalHref(url)}` on every chip. React 18.3.1 only *warns* on a
`javascript:` href — it does not block it — so React is not the boundary. Layer 1 is the server
write gate, layer 2 is the server read filter, and layer 3 exists because a defence that costs six
lines and closes a stored-XSS sink is worth having even when the first two hold. Every chip carries
`target="_blank" rel="noopener noreferrer"` — both, stated.

**Empty states.** Zero renderable links → **the whole Links card does not render** for a
non-manager; on a read-only profile an empty section is clutter. For a manager the card renders
with **No links yet.** at `text-caption text-graytext-mid` plus the **Edit** control, because the
manager needs the entry point.

**The withheld nudge.** In the Links card header, when `withheldPlatforms.length > 0` **and**
`canEdit`, render a `Badge tone="warn"` reading **{n} link needs attention** / **{n} links need
attention** beside the **Edit** control. A manager should not have to open the editor to learn
something is wrong. **A non-manager never sees this badge** (P-05b).

**Wire the card into `OrgProfile.tsx`** at the declared Links mounting point, between Profile and
Brand kit — the section order is locked. Read mode renders `SocialLinksRow`; edit mode renders
`SocialLinksEditor`. On success fire `addToast('Links saved', 'success')`, leave edit mode, and
**re-render the read view from the server's response, never from local form state** — the server
normalises what it stores (a tab inside a hostname is silently removed by the URL parser), and the
user must see what was actually saved.

**Never** render a disabled link, the raw URL as a label, a link without `rel="noopener noreferrer"`,
or use `dangerouslySetInnerHTML` — there are zero occurrences in `frontend/src` today and this phase
adds none.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Flask API → React `href` sink | A stored URL reaches an anchor; layer 3 applies even though layers 1 and 2 already filtered it. |
| withheld link data → DOM | The URL that failed the safety check must not enter the document at all, in any attribute or any value. |
| manager view ↔ reader view | Information a manager may act on must not leak into the view a reader gets. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-53 | Tampering | stored URL in an `href` | high | mitigate | `safeExternalHref` on every chip; React omits the attribute for a non-`http(s)` value and the chip renders as inert text. React's own `javascript:` handling is warn-only at 18.3.1 and is not counted as a control. |
| T-04-54 | Information Disclosure | withheld URL reaching the DOM | high | mitigate | `withheld_platforms` carries keys only (enforced server-side in 04-02); the editor renders a withheld row with an **empty** input and never a value. Asserted by a grep for withheld vocabulary in the read component and a page-source check in the manual step. |
| T-04-55 | Information Disclosure | disclosing a hidden link to a reader | medium | mitigate | No count, no placeholder, no reserved space on the read view; the nudge badge is guarded on `canEdit` (P-05b). |
| T-04-56 | Tampering | reverse tabnabbing | low | mitigate | `target="_blank" rel="noopener noreferrer"` on every chip. |
| T-04-57 | Tampering | client re-validating URLs and diverging from the server | medium | mitigate | Save stays enabled; the client never pre-validates a URL. One validator, server-side; the client's only URL logic is the scheme check in `safeExternalHref`, which is a render-time refusal rather than a second write rule. |
| T-04-58 | Repudiation | user believing a value saved that did not | medium | mitigate | The read view re-renders from the server's response, never from local form state, so a normalised value is visibly what was stored. |
</threat_model>
