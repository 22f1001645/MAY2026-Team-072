# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** the eight UI surfaces Phase 4 touches (see `## Surface Contracts`). Everything else in `frontend/` is inherited and out of scope.

**Governing principle for this phase:** every token, class string and primitive named below already exists in the codebase unless explicitly marked `NEW`. This is a brownfield design system derived from the EKATVA Brand Kit v1.0. Phase 2 established the extension rules; Phase 3 added zero primitives; **this phase adds exactly one** (`Textarea`, and only on the Phase 2 `Select` precedent — a class string already copy-pasted four times).

**The one sentence that governs the whole phase:** this is the first surface in Ekatva OS where a user's own words, a user's own image bytes and a user's own URLs are rendered back to other people — so every contract below exists to make *what the server actually vouches for* the thing that reaches the screen, and to make everything it refuses **absent rather than broken**.

## Spacing Scale

Base unit 4px. Declared values — **8-point scale, no 12px member**:

| Token | Value | Tailwind | Usage in this phase |
|-------|-------|----------|---------------------|
| xs | 4px | `p-1`, `gap-1` | badge icon-to-label gap; the gap between a field and its character counter |
| sm | 8px | `gap-2`, `mt-2`, `space-y-2`, `py-2` | swatch-row and phrase-row inner gap and vertical padding; the gap between Save and Cancel; the palette chip row gap; the gap between the six platform rows |
| lg | 16px | `px-4`, `gap-4`, `mb-4` | row horizontal padding; the label-to-field stack inside each section; the section header row |
| xl | 24px | `p-6`, `space-y-6` | every profile `Card` uses `p-6`; the gap between the three sections (`space-y-6` on the page column) |
| 2xl | 32px | `mb-8` | separation between the identity header block and the first section card |
| 3xl | 48px | `py-12` | the 404 card's vertical padding |

**Vertical rhythm rules for this phase:**
- The page is a single column: identity header → `mb-8` → `space-y-6` stack of Profile / Links / Brand kit. `space-y-6` owns **every** gap between sections; no section adds a margin of its own.
- Section order inside `OrgProfile.tsx` is **locked**: **Profile (logo + bio) → Links → Brand kit.** Identity before contact before voice. The brand kit is last because it is the only section a reader never sees (S6), so it must not sit between two sections that everyone sees.
- Inside a section `Card p-6`: header row (`mb-4 flex items-center justify-between`), then the field stack at `space-y-4`, then the action row at `mt-6`.
- The row shell used by the palette swatches, the sample phrases and the six platform rows is **one string, used verbatim in all three**: `flex items-center gap-2 rounded-xl border border-white/10 bg-white/[0.02] px-4 py-2`. Three lists on one page at three row heights would read as three unrelated widgets.

**12px is not a member of this phase's scale, and this phase's inherited-12px list is empty.**

Phase 3 carried a closed five-row list of inherited 12px values, each justified by adjacency to an existing 12px element in the file being extended. **Phase 4 inherits none of them.** `OrgProfile.tsx` is a new file with no adjacent legacy rhythm, and the only existing file this phase touches (`Orgs.tsx`, S8) is changed in logo *source* and *tint* only — not in any spacing value. **No new `gap-3`, `mb-3`, `mt-3`, `space-y-3`, `py-3` or `px-3` may appear anywhere in this phase.** The `Textarea` primitive's `px-4 py-3` is the one exception and it is inherited verbatim from the lifted string, listed below.

**Exceptions (documented, not to be "fixed") — NOT part of the declared scale above.**

## Typography

Four declared sizes. All are existing `tailwind.config.js` tokens except the 14px control size, the established arbitrary value throughout the app.

| Role | Size | Weight | Line Height | Token | Applied to |
|------|------|--------|-------------|-------|-----------|
| Heading | 20px | 600 | 1.4 | `text-h3` | the three section headings (**Profile**, **Links**, **Brand kit**), dialog titles |
| Body | 16px | 400 | 1.6 | `text-body` | the bio as read; the voice/tone text as read; dialog consequence lines |
| Control | 14px | 500 (600 when it is a value rather than a label) | 1.4 | `text-[14px]` | every field value, every hex value, org name in the switcher, button labels (`Button size="md"`), the platform name beside a rendered link |
| Caption | 12px | 600 when a label (`uppercase tracking-wider`), 400 when a sentence | 1.5 | `text-caption` | field labels, hints, character counters, error bodies, the fallback disclosure line |

**Weights — exactly two declared:** `400` (regular) and `600` (semibold).

**Weight exception (inherited, not introduced):** `Button` hardcodes `font-bold` (700), `SectionTitle` renders its `h1` at `font-bold`, and `Badge` renders at `font-medium` (500). All three are pre-existing brand-kit decisions. **This phase introduces zero new 700-weight text.** The scoped reading of 500 that Phase 3 locked is inherited unchanged: 500 is the control-row weight and appears only where the codebase already puts it. Every *new* string this phase authors is 400 or 600.

**Page title** is the existing `SectionTitle` primitive (36px / 700 / 1.2, `text-h1`, `text-gold`), rendering the organisation's name with the eyebrow **Organisation**. Inherited wholesale.

**Casing rules:**
- `uppercase tracking-wider` is reserved for 12px labels and eyebrows only. Never on 14px or larger.
- **Organisation names, bios, voice/tone text, sample phrases and hostnames are rendered exactly as stored** — never uppercased, never title-cased in CSS. A `text-transform` on user data corrupts acronyms (`IITM BS`) and proper nouns, and on a hostname it would change the meaning of the string.
- **Hex values render lowercase**, e.g. `#5ce6c9`. The server stores lowercase (`^#[0-9a-f]{6}$` after `.lower()`); displaying uppercase and storing lowercase is a discrepancy the user sees on the next reload. The hex `Input` normalises to lowercase on blur.
- Platform names render as the fixed display labels in `## Copywriting Contract → Platform labels`, never as the stored key (`x`, `github`).

## Color

Dark surface only. Percentages are share of painted pixels on the `/orgs/:orgId` route.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(0.13 0.015 175)` — Oneness Black, ~`#030907` (`bg-onyx`) | page background, main column, dialog panel, `Input`/`Select` fill |
| Secondary (30%) | `from-white/[0.04] to-white/[0.01]` + `border-white/5` (`Card`) for the three sections; `bg-white/[0.02]` + `border-white/10` for every row shell; `bg-white/[0.03]` for the `Textarea` fill | the three profile sections, all link / swatch / phrase rows, the logo tile's neutral state |
| Accent (10%) | `#5CE6C9` — Ekatva Teal (`teal`) | see reserved list below |
| Accent–warm (inside the same 10% budget) | `#FFCF96` — Unity Gold (`gold`) | `SectionTitle`, section `h2`s, and **one** new surface: the AI-draft strip (S7) |
| Destructive | `red-300` text on `border-red-400/40` with transparent fill (`Button variant="danger"`); `border-red-400/30 bg-red-500/10 text-red-300` for inline error strips; `border-red-400/50` on a rejected field | **Remove logo**, **Discard draft**, every server-rejection strip, an over-length counter |
| Caution | `border-amber-400/25 bg-amber-400/10 text-amber-300` (`Badge tone="warn"`) | the **Hidden** marker on a withheld link and the **{n} link needs attention** count. Amber, not red — the user did nothing wrong. |

**Teal accent is reserved for exactly these elements in this phase:**
1. Primary CTAs — **Save changes**, **Save links**, **Save brand kit**, **Upload a logo**
2. Focus rings — `focus:outline-none focus-visible:ring-2 focus-visible:ring-teal/50` on every interactive element in this phase, without exception, including the `<input type="color">` and the hidden file input's visible label
3. Inline text links, including every **rendered social link and the website link** (S5)
4. The `Input` / `Select` / `Textarea` focus border already in those primitives

**Teal is explicitly forbidden on:**
- the **Edit** control — it is `variant="secondary"`. Edit opens a form; it does not commit anything, and a teal Edit beside a teal Save puts two equal-weight CTAs in one header.
- the **Draft with AI** control — it is `variant="secondary"`. The AI draft is an offer, not the task; **Save brand kit** is the task.
- the AI-draft strip, its border and its icon (gold — a state notice, not an action)
- the logo tile background when an uploaded logo renders (see the tint rule in S3)
- any palette swatch chrome. A swatch's border is `border-white/20`, never teal — teal chrome on a user's own colour would misread as "selected".
- any disabled control, in either the unauthorised or the busy variant
- decorative dividers, card borders, or section rules

**Gold budget — the running ledger.** Phase 2 painted exactly one gold *surface* (the academic banner). Phase 3 added exactly one gold *element* (the Mega Meetup badge). **Phase 4 adds exactly one gold surface — the AI-draft strip (S7)** — and it does so by **reusing Phase 2's banner class string verbatim** (`flex items-start gap-3 rounded-xl border border-gold/25 bg-gold/[0.06] px-4 py-3`), not by authoring a new gold treatment. No second gold surface may be added in Phase 4.

> The `gap-3` inside that class string is part of the inherited Phase 2 banner string and is lifted whole. It is **not** a licence for 12px anywhere else in this phase — see the spacing rule above.

**Status color mapping — locked, and never the only channel:**

| State | Channel 1 (colour) | Channel 2 (text) | Channel 3 |
|-------|--------------------|------------------|-----------|
| Link withheld by the read filter | `Badge tone="warn"` | the word **Hidden** | the caption sentence beneath the field |
| Manager has withheld links | `Badge tone="warn"` in the section header | **{n} link needs attention** | the count itself |
| AI draft pending | gold strip | **This is an AI draft. Nothing is saved yet.** | the **Discard draft** control, present only in this state |
| Counter over its limit | `text-red-300` | **{n}/200 — trim {n−200} characters.** | the number itself |
| Field rejected by the server | `border-red-400/50` on the field | our heading + the server's sentence beneath | the heading names the field |
| Logo is a built-in fallback | none | **Using the built-in {House name} mark** | rendered only in edit mode, never on the read view |

**A colour is data on this page, and that is exactly why colour is never the only channel.** The palette swatches *are* colours the user chose — including ones that may be near-invisible on our dark surface. Every swatch therefore carries (a) a `border-white/20` outline so a `#050505` chip still reads as a square, and (b) its lowercase hex string in an adjacent 14px field which is the authoritative, copyable, screen-reader-legible channel. **The hex text, not the chip, is the value.**

**Contrast floors (AA, verified against `#030907` / the card gradient):**
- `text-offwhite` `#F8F8F8` — primary text, all user-supplied names, bios, phrases and hex values
- `text-graytext-light` `#AAAAAA` — secondary text, ≥14px only, and 12px only for `font-normal` sentences that duplicate a channel already carried elsewhere
- `text-graytext-mid` `#666666` — decorative and tertiary only (placeholders, empty-bio line, character counters under their limit). **Never** the sole carrier of a state, a label, or an instruction.
- `text-teal`, `text-gold`, `text-red-300` and `text-amber-300` all clear 4.5:1 on `bg-onyx` and on the `Card` gradient.
- **No contrast claim is made about a user's palette swatch.** It is content, not chrome, and nothing is rendered *on top of* it.

### Primary visual anchor

**`/orgs/:orgId`:** the anchor is the existing `SectionTitle` carrying the organisation's name (36px/700 gold). Rank order: **(1) `SectionTitle` → (2) the logo tile → (3) the section headings → (4) everything else.** The logo is second because the whole point of ORG-01 is that an organisation now has a face; on a page titled with a name, the image beside the name is the second thing the eye should reach.

**Enforceable consequence:** if the logo tile ever out-shouts the title in review, the fix is to shrink or quiet the tile, **never** to enlarge `SectionTitle` — which is inherited and shared by 20 pages.

### Copy rules that apply to every string in this phase

- **A rejection reason is the server's sentence, shown verbatim, under our heading.** The heading is ours and is specific per `code`; the body is `error.message` from the `{ error, code }` envelope. Never paraphrase — inherited from `03-UI-SPEC.md:259` and re-confirmed for every rejection in this phase.
- **Never say "you can't."** Where a control is unavailable, the line names the condition or who *can* — **Finish editing {section} first.**, **AI drafting isn't set up on this server.** Inherited from Phase 2.
- **Never announce a hidden thing to someone who cannot act on it.** A withheld link is invisible to a reader and disclosed to a manager. This is a copy rule, not just a layout rule: there is no "1 link hidden" string anywhere in this phase.
- **State the consequence before the act, and count that as the confirmation.** Both dialogs in this phase name the outcome in their body; neither asks twice.
- **The bare "Cancel" exception, re-checked rather than assumed.** Phase 2's rule: a dismiss is labelled **Cancel** when it is one of exactly two buttons in a dialog the user opened deliberately, and dismissing writes nothing. This phase uses bare **Cancel** in four places — the three section edit-mode dismisses and both dialogs — and every one satisfies the conditions. Nothing in this phase is labelled **Close**.
- **Every icon-only control carries an accessible name.** The three remove buttons and the logo remove control each take an `aria-label` (and matching `title`) naming the object they act on: **Remove colour {hex}**, **Remove phrase {n}**, **Remove the logo**. This is in addition to the 36px minimum box, not instead of it.
- **User data is rendered as stored.** Bios, phrases, org names and hostnames are never re-cased, never trimmed for display, never title-cased in CSS.

### Forbidden vocabulary in user-facing strings

Never render to a user: `POR`, `capability`/`capabilities`, `manageableOrgIds`, `token`, `JWT`, `400`, `403`, `413`, `422`, `503`, `allowlist`, `hostname` (as a label — the *value* is fine), `scheme`, `payload`, `mutation`, `endpoint`, `logo_url`, `org_id`, `brand_kit`, `ai_available`, `has_kit`, `withheld_platforms`, `XSS`, `sanitise`, `validator`, `Gemini`, `LLM`, `prompt`, `model`. These are implementation words.

Two consequences worth stating:
- **The AI provider is never named.** The copy says **AI**, never "Gemini". The provider is swappable behind a lazy-import seam and a user-facing brand name would make a config change into a copy change.
- The user-facing word for an `Organisation` is **organisation** (never "org" in prose — acceptable only inside a 12px label where space is genuinely constrained), and the user-facing word for a social-link target is the **platform's own name**, never "platform" as a noun addressed to the user.

An unbounded free-text field rendered on a public profile is an overflow surface. **This contract sets 1000 characters** (counter from 800, same over-limit treatment) and the planner must add `Length(max=1000)` to `OrgProfileSchema` in plan 04-01. ### S7 — The AI draft flow (ORG-04 · ROADMAP criterion 4 — the most interaction-heavy surface in this phase)

Criterion 4 in full: *"An organisation with no brand kit can request an AI-drafted starting kit, edit every field, and nothing applies until they explicitly save it."* Every state below exists to make the last clause observable.

**The structural decision:** a returned draft **populates the live form fields in place.** There is no preview panel, no side-by-side diff, no modal, and no "Apply draft" button. Rationale: criterion 4 requires the user to be able to edit *every* field, and a preview-then-apply flow creates a second write surface and a second review moment — which is precisely the *"a second brand-kit writer"* anti-pattern `04-RESEARCH.md` names. **`PUT /brand-kit` is the only writer, and `Save brand kit` is the only button that reaches it.**

| State | Trigger | Contract |
|-------|---------|----------|
| **A0 — Render-locked (`ai_available: false`)** | `GET /brand-kit` reports `ai_available: false` | `Button size="sm" variant="secondary"` **Draft with AI**, `disabled` **and** `aria-disabled="true"`, `opacity-40 cursor-not-allowed`, a 12px padlock glyph immediately before the label, and a **visible** line beneath at `text-caption text-graytext-light`: **AI drafting isn't set up on this server. Fill the kit in yourself — every field below works without it.** — plus the same string as `title`. Stays hoverable and focusable; **never `pointer-events-none`.** **Never a bare disabled button. Never hidden. Never a 503 surfaced as a red error on page load.** |
| | | **This is a third trigger for the render-locked exception, added by this phase.** Interaction State A permits render-locking when (a) removing the control breaks a layout read as a checklist, or (b) the capability is plausibly acquirable. Neither applies — this is a server feature flag, not a capability. The new trigger is **(c) the control's absence would be indistinguishable from the feature not existing, and a phase success criterion requires the feature be discoverable.** `04-RESEARCH.md` D-10 already directs this outcome; this row is where the rule that permits it is written down. |
| **A1 — Available, no kit** (`ai_available: true`, `has_kit: false`) | default | `Button size="sm" variant="secondary"` **Draft with AI**, in the Brand kit card header. Caption beneath at `text-caption text-graytext-light`: **Gives you a starting point. Nothing is saved until you press Save brand kit.** |
| **A2 — Available, kit exists** (`has_kit: true`) | default | The control still renders, labelled **Draft a new version with AI**, caption **This replaces what's in the form. Your saved kit isn't touched until you press Save brand kit.** ORG-04's *"for organisations that don't have one yet"* scopes who the button is **for**, not a hard gate; the endpoint is deliberately unconditional (04-RESEARCH D-9, so a legitimate "start over" is not blocked), and a UI that hides the button after the first save makes that path unreachable with no explanation. **When the form is dirty**, pressing it opens the S7-D confirm first. When the form is pristine, it drafts immediately — discarding restores the saved kit, so there is nothing to lose. |
| **A3 — In flight** | the draft request is open | Interaction State B: label → **Drafting…**, `disabled aria-busy="true"`, minimum 300ms visible. Every field in the Brand kit card goes `disabled` for the duration; the Profile and Links sections do not. Because this is an LLM round trip measured in seconds, **after 1200ms** a caption appears beneath: **Still drafting — this takes a few seconds.** A **30-second client-side abort** ends the request and routes to A5 with the generic heading. |
| **A4 — Draft returned (draft-review state)** | 200 | The fields fill in place, the section enters edit mode if it was not already, and a **gold strip** renders directly above the field stack, reusing Phase 2's banner class string verbatim: `flex items-start gap-3 rounded-xl border border-gold/25 bg-gold/[0.06] px-4 py-3`, with `role="status"` (**not** `role="alert"` — nothing is wrong). Title at `text-[14px] font-semibold text-offwhite`: **This is an AI draft. Nothing is saved yet.** Body at `mt-1 text-caption text-graytext-light`: **Edit anything below, then press Save brand kit. Discard draft puts back what was there before.** Action in the strip: `Button size="sm" variant="ghost"` **Discard draft**. |
| | | **The draft is atomic.** The strip covers the whole form; there is no per-field "from the AI" marker. Six provenance captions scattered through a form is clutter, and once the user edits one field the per-field claim stops being true anyway. |
| | | **The draft is never cached.** Not in a persisted React Query key, not in `localStorage`, not in `sessionStorage`. It lives in component state and dies with the component. A draft that survived a reload would be indistinguishable, to anyone reading criterion 4, from something having been applied. |
| **A5 — Failure** | 503 or abort | An inline strip **above the Draft control** (never in the Save error slot, which belongs to `PUT`): `rounded-xl border border-red-400/30 bg-red-500/10 px-4 py-3`, heading at `text-[14px] font-semibold text-red-300`, body at `mt-1 text-caption text-red-300`. Heading chosen from `code`, never by string-matching: `ai_unavailable` → **AI drafting isn't available right now** · `ai_failed` → **The draft didn't come through** · anything else, including the client abort → **Could not draft a brand kit**. Body: the server's `message` verbatim; for the abort, **Nothing changed. Try again, or fill the kit in yourself.** Every field keeps whatever it held. The button re-enables. **Never toast-only.** |
| | | On `ai_unavailable` specifically — meaning `ai_available` was stale because the key was removed server-side mid-session — the button **also flips to A0 for the rest of the session**, so a second click cannot repeat the same failure. |

**S7-D — Discard draft**

| Property | Contract |
|----------|----------|
| Effect | Restores the form to the last-saved kit, or to an empty form when `has_kit === false`. The strip unmounts. **No request is sent. No toast fires.** Nothing was ever on the server to undo. |
| Untouched draft | Discards immediately, no confirmation. The model's words are not the user's work. |
| Edited draft | A single-step `Dialog`, `max-w-md`: title **Discard your edits?** · body `text-body text-graytext-light` **You've changed the draft. Discarding puts back {the kit you saved earlier \| an empty form}.** · actions `Button variant="ghost"` **Cancel** + `Button variant="danger"` **Discard draft**. The threshold is the user's own typing, not the draft's existence. |
| Bare `Cancel` | Inherited convention, and it satisfies all three conditions Phase 2 set: two buttons, a dialog the user opened deliberately, and dismissing writes nothing. |

**S7-N — Navigating away without saving (the criterion-4 observable)**

| Case | Contract |
|------|----------|
| In-app navigation (sidebar, switcher, any `<Link>`) | **Not blocked.** The draft is discarded and nothing is saved — which is exactly what criterion 4 demands. The disclosure happens *before* the loss, in the strip's own first sentence (**Nothing is saved yet.**), not as a confirm afterwards. |
| Why no blocker | `react-router-dom` v6's `useBlocker` requires a data router (`createBrowserRouter`); this app renders `<Routes>` inside a plain `<BrowserRouter>`, and migrating is a framework change the standing "no new frameworks" constraint forbids. A hand-rolled navigation interception is fragile and would be a second mechanism competing with the router. **Recorded so this is a decision, not an omission.** |

| Returning to the page | The form shows the **saved** kit — or **No brand kit yet.** — with no strip, no draft, and no trace. ## Interaction States

Inherited from Phase 2's contract and Phase 3's re-confirmation, with this phase's instances named and **one documented extension** (trigger (c) below).

### A — Not permitted

**Default: do not render.** A user who does not manage this organisation sees no Edit control, no Save control, and no Brand kit card. This is S2's whole point: cross-org denial is invisible.

**Render-locked exception**, permitted only under one of three triggers:

| Trigger | Status | This phase's instance |
|---------|--------|----------------------|
| (a) removing the control breaks a layout the user reads as a list or checklist | inherited from Phase 2 | none in this phase |
| (b) the user could plausibly acquire the capability | inherited from Phase 2 | **Edit** on sections B and C while section A is in edit mode (**Finish editing {section} first.**); **Save** after a mid-edit capability loss (**Your access to this organisation changed…**) |
| **(c) the control's absence would be indistinguishable from the feature not existing, and a phase success criterion requires the feature be discoverable** | **NEW, added by this phase** | **Draft with AI** when `ai_available === false`. ORG-04 and ROADMAP criterion 4 are about a feature the user must be able to *find*; hiding it when the server key is unset would make the feature untestable in UAT and would make a configuration problem look like a missing product. `04-RESEARCH.md` D-10 directs this outcome; this row is where the permitting rule is recorded. |

| Channel | Value |
|---------|-------|
| Disabled attributes | `disabled` **and** `aria-disabled="true"` |
| Visual | `opacity-40 cursor-not-allowed` (inherited from `Button`'s disabled base) |
| Marker | A 12px padlock glyph immediately before the label |
| Explanation | A **visible** line beneath, `text-caption text-graytext-light`, plus the same string as `title`. A tooltip alone is unreachable on touch. |
| Pointer events | Stays hoverable and focusable. **Never `pointer-events-none`.** |
| Label | Unchanged. Never gains an ellipsis or a spinner. |

### B — Busy (request in flight)

| Channel | Value |
|---------|-------|
| Disabled attributes | `disabled` **and** `aria-busy="true"`. **Never** `aria-disabled` — it is working, not unavailable. |
| Visual | `disabled:opacity-40` from the `Button` base. No padlock, no explanatory line. |
| Label | Present-participle form of its own verb: **Saving…** (Save changes / Save links / Save brand kit), **Uploading…**, **Removing…**, **Drafting…** |
| Minimum duration | 300ms visible |
| Extended duration | Only the AI draft (A3) adds a >1200ms caption. No other request in this phase is expected to be slow, and none gets a progress bar. |
| Scope | Sibling controls in the **same section card** go `disabled`; the other two sections do not. Saving the bio must not freeze the links editor. |

### The discriminator, stated for the reader

> A **busy** control keeps its own verb and gains an ellipsis.
> An **unauthorised or blocked** control keeps its label unchanged, gains a padlock, and gains a sentence naming the condition.

Never both, never in the same frame.

### C — Blocked by a fixable precondition

**Every Save control in this phase stays enabled.** **Save changes**, **Save links** and **Save brand kit** are never pre-disabled for a malformed URL, a bad hex, an over-length phrase or an empty field. The server rejects, the offending field is marked, and the server's own sentence is the reason.

This matters more here than anywhere in Phase 3, because **every rule on this page lives on the server by design** — the host allowlist, the magic-byte sniff, the hex regex, the length caps. A client that pre-disabled on its own guess of those rules would be a second, weaker copy of the very validator this phase exists to centralise, and the first time the two disagreed the user would face a grey button with no explanation at all.

**This is the rule most likely to be "helpfully" broken during implementation. It is deliberate.**

### Focus, motion and dirty-state, globally

- Every interactive element added in this phase carries `focus:outline-none focus-visible:ring-2 focus-visible:ring-teal/50`. **No exceptions** — including the visually-hidden file input's styled `<label>` and the `opacity-0` `<input type="color">`, both of which would otherwise swallow the focus indicator.
- All transitions use `duration-200 ease-material` (`cubic-bezier(0.4, 0, 0.2, 1)`).
- `prefers-reduced-motion` is handled app-wide in `index.css`; no component-level handling is needed or permitted.
- A section in edit mode with unsaved changes registers the `beforeunload` listener (S7-N) and deregisters it on save or cancel. Exactly one listener, owned by the page, never one per section.

## Accessibility Contract

Named explicitly because this phase introduces three control types the app has never shipped: a file input, a colour input, and a user-supplied external link.

| Concern | Contract |
|---------|----------|
| File input | Visually hidden `<input type="file">` wrapped by a styled `<label>`. The label is the focusable, keyboard-activatable control and carries the teal focus ring. A bare hidden input with a `<div>` trigger is not keyboard-reachable and is forbidden. |
| Colour input | The `opacity-0` `<input type="color">` is a real input, focusable, with `aria-label="Pick colour {n}"`. **The adjacent hex text field is the accessible path and is never disabled, never read-only, and never removed** — native colour pickers are not uniformly keyboard-operable, so typing must always work. |
| Icon-only controls | 36px minimum box **and** an `aria-label` naming the object, **and** the same string as `title`. Both, always. |
| External links | `target="_blank" rel="noopener noreferrer"`, label is the platform name or hostname (never a bare glyph), full URL in `title`. |
| Live regions | The AI-draft strip is `role="status"` (nothing is wrong). Every server-rejection strip is `role="alert"` (something is wrong and must interrupt). The >1200ms drafting caption is inside the `role="status"` region and announces once. |
| Rejection focus | On a section-level rejection the strip is scrolled into view (`scrollIntoView({ block: 'center' })`) and receives focus (`tabIndex={-1}`). On a **field**-level rejection, focus moves to the first offending field instead — the message is beside it, and moving focus to a strip the user then has to navigate away from is a step backwards. |
| Dialog focus | Trapped while open, returned to the triggering control on close. `Esc` and overlay click both cancel. Initial focus lands on the dismiss (`Cancel`) in both dialogs, because both confirm a loss. |
| Headings | One `h1` (the `SectionTitle`), three `h2` section headings. The identity badge row is not a heading. |
| Colour-blind safety | Every state in `## Color → Status color mapping` carries at least two channels. The palette swatches are the one place colour is the *content*; the hex text is the authoritative channel and is always present. |

### ⚠️ Contract additions this UI-SPEC originates — the planner must carry all four

These are not observations; they are requirements this contract cannot be implemented without. Each is small and each belongs to a named plan.

| # | Addition | Plan | Why the UI cannot do without it |
|---|----------|------|--------------------------------|
| 1 | `GET /orgs/<org_id>/profile` returns `withheld_platforms: [<key>, …]` — **keys only, never the URL, never a reason** | 04-02 | Without it the editor is populated from the filtered payload and a link that stopped rendering is indistinguishable from one never saved. The key is already public; the URL is the string that failed the check and must not reach the DOM. |
| 2 | `social_url_scheme` / `social_url_host` carry `details: { platform: "<key>" }`, or `details: { field: "website" }` | 04-02 | Without it a 400 cannot be placed on the row that caused it, and the user hunts. Degraded fallback: render at section level. |
| 3 | `OrgProfileSchema` bounds `bio` at `Length(max=1000)` | 04-01 | `organisations.bio` is an unbounded `db.Text`. A client-side counter over a server with no cap is a promise the server does not keep, and an unbounded field on a public profile is an overflow surface. |
| 4 | `api.ts`'s `request` helper must not throw on a **non-JSON error body** | 04-03 | Flask's `MAX_CONTENT_LENGTH` 413 returns HTML. A JSON parse error instead of **That file is {n} MB. The limit is 2 MB.** turns the phase's most predictable rejection into an unhandled exception. |
