# 07-UI-SPEC — Phase 7: Progression Gating

> Visual and interaction contract. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase goal (ROADMAP):** an organisation's ability to propose bigger events unlocks from its own completed track record, enforced by the server and *explained* in the UI.

**Design principle for this phase:** every gate reads as a **rule with a next step**, never as a broken or missing control. A locked option says what is missing and where; a refused submit says the shortfall by number. This is the same choice Phase 5 made for `PushLiveGate` (D-07) and Phase 4 made for `LockedControl` — Phase 7 reuses both rather than inventing a third lock idiom.

| Role | Token | Size | Weight | Line height |

## 4. Color

| Role | Value | Usage |
|---|---|---|
| Dominant (60%) | `onyx` `oklch(0.13 0.015 175)` + `offwhite` `#F8F8F8` text | Page ground and all body copy on every Phase 7 surface |
| Secondary (30%) | `Card` substrate — `bg-gradient-to-b from-white/[0.04] to-white/[0.01]`, `border-white/5` | Scale cards, collaborator card, sponsorship banner |
| Accent (10%) | `teal` `#5CE6C9` / `teal-accent` `#3FD4B6` | See reserved list below |
| Celebration | `gold` `#FFCF96` | **Only** the PROG-03 sponsorship-unlocked banner (heading, border `gold/20`, wash `gold/[0.06]`, city badges `tone="gold"`) — mirrors the existing quota-notice strip in `ProposalNew` |
| Rejection | `red-300` + `border-red-400/30` + `bg-red-500/10` | `ErrorStrip` on a refused submit / refused approve only |
| Muted / locked | `graytext-mid` `#666666`, `graytext-light` `#AAAAAA` | Locked scale card text, lock icon, unmet progress lines |

**Accent (teal) reserved for exactly:**
1. The **selected** scale card border + wash (`border-teal bg-teal/10`) — existing behaviour, unchanged.
2. The **met** half of a progress line in the fest lock caption (the "✓ Local meetup" tick and its numeral).
3. The accepted-count numeral when the fest collaborator threshold **is met** (`text-teal` on "6 of 6 organisations named").
4. Focus rings (`focus:ring-teal/50`) — inherited from primitives.

**Accent explicitly NOT used for:** the locked state of the fest card (locked is `graytext-mid`, never a dimmed teal), the sponsorship banner (gold owns celebration), any hover state on a locked control.

**Destructive actions in this phase: none.** Progression gating is read-and-refuse only — nothing is deleted, revoked or made irreversible from the UI. No destructive confirmation copy is required.

## 5. Surfaces

### 5.1 Fest scale lock — `ProposalNew.tsx`, Step 1 scale selector (D-04, PROG-01)

Modify the **existing** scale-option `<button>` map (L201-222) in place. No new component file — only `regional_fest` can be locked, and a `<ScaleOption>` abstraction with one locked product is an interface for one implementation.

Eligibility arrives from a new query hook (`useFestEligibility(orgId, city)` in `lib/queries.ts`), refetched whenever `form.org_id` **or** `form.city` changes. It returns both counts independently — never one boolean — because the caption must name *which* half is missing.

**Unlocked (eligible) — no visual change.** The card renders exactly as today.

**Locked** (`regional_fest` only):

```
<button type="button" aria-disabled="true" aria-describedby="fest-lock-reason"
  onClick={noop}
  className="rounded-xl border border-white/10 bg-white/[0.02] p-4 text-left
             opacity-60 cursor-not-allowed transition-all duration-300 ease-material">
```

- Title row: `flex items-center gap-1.5` — 12px lock SVG (path copied from `LockedControl`, `aria-hidden`) in `text-graytext-mid`, then `Regional Fest` in `text-[14px] font-semibold text-graytext-mid` (not `text-offwhite` — a locked option is not a live option).
- Sub: `text-caption text-graytext-mid` — `230+ · sponsors` (unchanged).
- Progress caption `id="fest-lock-reason"`, `mt-2 space-y-0.5 text-caption`:
  - Met line: `text-teal` — `✓ Local meetup in {City}`
  - Unmet line: `text-graytext-mid` — `Regional meetup in {City} — not yet`
  - Summary line: `font-semibold text-graytext-light` — `Locked · 1 of 2 completed`
- **Hover:** none. No `hover:border-teal/40` on the locked card — a hover affordance on a dead control is a lie.

**Auto-revert:** if `scale === 'regional_fest'` and the org/city change makes it locked, `setScale('regional_meetup')` and render a `mt-3 rounded-xl border border-gold/20 bg-gold/[0.06] px-4 py-2 text-caption text-graytext-light` notice for that render pass (dismissed by the next scale click). Copy in §6.

**Indeterminate (no org or no city chosen yet):** card is locked with summary line replaced by `Pick a city to check eligibility.` and no ✓/not-yet lines.

**Loading:** card is locked, summary line reads `Checking eligibility…`, no ✓/not-yet lines, no spinner (a 8-word inline string beats a spinner on a 40px caption).

**Fetch error: fail closed.** Card stays locked; summary line reads `Couldn't check eligibility. The server enforces this on submit.` The server is the real gate (PROG-04) — an optimistically-unlocked card would trade one clear message for a 403 three steps later.

### 5.2 Fest collaborator counter — `ProposalNew.tsx`, Step 3 collaborating-orgs card (D-01 named check, PROG-02)

Modify the existing counter caption (L547-556) in place. Non-fest scales keep today's copy verbatim (including the Mega Meetup hint). For `scale === 'regional_fest'` the caption is replaced by a threshold counter:

- Shortfall: `mt-2 text-caption text-graytext-light` — count numeral in `font-semibold text-gold`, e.g. **`4 of 6 organisations named`** on line 1, `Name 2 more to submit a Regional Fest.` on line 2 (`text-graytext-mid`).
- Met: numeral in `font-semibold text-teal` — `6 of 6 organisations named`, line 2 `Each Secretary must accept before an admin can approve.` — this second line is load-bearing: it is the only place the named-vs-accepted split (D-01) is explained before the admin queue.
- The count includes the primary org. Copy therefore says "organisations", never "collaborators", so the +1 is not surprising.

The `Submit proposal` button stays enabled — the server owns rejection (PROG-04), and a disabled submit would hide the reason. A short fest proposal is refused inline by §5.3.

### 5.3 Submit rejection — `ProposalNew.tsx` existing error block (PROG-04)

The existing `submitMut.isError` alert (L569-574) already renders `errorHeading(code)` + message. Phase 7 adds two entries to that page's `ERROR_HEADINGS` map:

| Code | Heading |
|---|---|
| `fest_locked` | `Regional Fest isn't unlocked here yet` |
| `fest_collaborators_required` | `A Regional Fest needs 6 organisations` |

Body text is the server's message verbatim (it names the shortfall by number). The block already carries `role="alert"`.

### 5.4 Approve-time refusal — `ApprovalQueue.tsx` (D-01 accepted check, PROG-04)

Two changes:

1. **Collaborator section header** (above the roster at L229): for `regional_fest` proposals only, render `text-caption font-semibold uppercase tracking-wider` with the live accepted count — `Collaborators · 4 of 6 accepted`, numeral `text-gold` when short / `text-teal` when met. Existing `CollabStatus` badges per row are unchanged.
2. **Refusal on approve:** replace the bare `decisionMut.isError` line (L303-307) with `<ErrorStrip>` (lift the same local-function pattern used in `OrgProfile.tsx`) so the refusal reads as a rule with a heading, and gets `role="alert"`. Heading `Not approvable yet`, body = server message.

### 5.5 Sponsorship unlock banner — `OrgProfile.tsx` (D-05, PROG-03)

A **local function component** at the bottom of `OrgProfile.tsx`, beside the existing `LockedControl` and `ErrorStrip` — the established local pattern on this page, no new file.

**Placement:** full-width strip inserted between the avatar/banner block (which ends `mb-24`) and the `grid grid-cols-1 ... md:grid-cols-[300px_1fr]`. Wrapper `mb-8`.

**Visibility:** rendered only when `canEdit` (the page's existing `manageableOrgIds`/admin gate — the same signal D-05 means by "Secretary/Deputy Secretary/RC") **and** the org has ≥ 1 `org_progression_unlocks` row. Otherwise renders `null` — no placeholder, no "not unlocked yet" state. An org that has not reached fest tier is not shown a locked promise.

**Visual:**
```
<section aria-label="Sponsorship and outreach status"
  className="mb-8 flex items-start gap-3 rounded-xl border border-gold/20 bg-gold/[0.06] p-4 animate-fade-up">
```
- Left: 18px gold key/unlock SVG, `text-gold shrink-0 mt-0.5`, `aria-hidden`.
- Heading: `text-[14px] font-semibold text-gold` — `Sponsorship & outreach tools unlocked`.
- Body: `mt-1 text-caption text-graytext-light` — copy in §6.
- City chips: `mt-2 flex flex-wrap gap-2`, one `<Badge tone="gold">` per unlocked city.
- Not dismissible, not collapsible — it is a standing status, not a notification.

## 7. Interaction, Animation & Accessibility

| Interaction | Spec |
|---|---|
| Eligibility refetch | Fires on `org_id` or `city` change only. No polling, no refetch on window focus (matches the 05-09 no-polling gate). |
| Locked card click | No-op. No shake, no toast — the reason is already visible below the card. |
| Locked card focus | `aria-disabled="true"`, **not** `disabled` — stays in tab order so a keyboard user reaches the reason (T-05-42 precedent, `PushLiveGate`). |
| Locked card ↔ unlocked transition | `transition-all duration-300 ease-material` on `opacity`/`border` — inherited from the existing card class. |
| Auto-revert notice mount | `animate-fade-up` |
| Sponsorship banner mount | `animate-fade-up` (page already wraps in `animate-fade-in`) |
| Counter numeral change | `transition-colors duration-200` on the gold→teal flip at threshold |
| Hover on locked card | None (see §5.1) |

**Accessibility:**
- Locked scale card: `aria-disabled="true"` + `aria-describedby="fest-lock-reason"` pointing at the progress caption; the caption is visible text, never a `title`-only tooltip.
- Progress caption region: `role="status" aria-live="polite"` so a screen-reader user hears the eligibility result after changing city without re-navigating the card.
- Lock, key and tick SVGs: `aria-hidden="true"`; the ✓ in `✓ Local meetup in {City}` is decorative and duplicated by the `Locked · 1 of 2 completed` summary.
- Sponsorship banner: `<section aria-label="Sponsorship and outreach status">`; city chips are plain text in `Badge`, no interactive role.
- Both `ErrorStrip` uses carry `role="alert"`.
- Contrast: `graytext-mid #666` on the `#0a0a0a`-family ground is ~5.0:1 — passes AA for the 12px caption. `gold #FFCF96` and `teal #5CE6C9` on the same ground exceed 10:1.

## 8. Responsive

| Breakpoint | Behaviour |
|---|---|
| `< 640px` | Scale grid already collapses to one column (`sm:grid-cols-3`); the locked card's progress caption gets full width — no truncation, it wraps. Sponsorship banner: icon + text stack stays `flex-row` (18px icon is not worth stacking); city chips wrap. |
| `640–1024px` | Scale cards 3-up; lock caption may wrap to 3 lines — card heights equalise via the existing grid. |
| `≥ 1024px` | Full layout. Sponsorship banner spans the full content width above the `[300px_1fr]` profile grid. |

Long city names (`Thiruvananthapuram`) appear in the lock caption and in badges — both **wrap**, never truncate. The city name is the load-bearing word in the sentence; a truncated one makes the rule unreadable.
