<objective>
Generate a mail-template draft whose tone comes from the organisation's brand kit and whose
facts come from the database — structurally, not by trusting the model.

Purpose: CAMPAIGN-01 says every factual detail is "template-interpolated by the backend, never
generated by the model". The only assembly shape that makes that *testable* is one where the
model's output is never the whole body: the server writes the facts and concatenates them after
the call returns. That single structural choice is what makes PROB-P1 provable and prompt
injection unable to alter a number.

Output: `generate_mail` with its fact block, accepted-collaborator traversal, injection-hardened
prompt and degraded fallback; the mail save endpoint; and `MailTemplateEditor.tsx`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| org-supplied brand text → LLM prompt | `voice_tone` and `sample_phrases` are free text authored by an organisation and become model input |
| Flask → Gemini | The only outbound third-party call in the application; the API key lives server-side only |
| Gemini response → mail body | Untrusted model output enters a document an organiser will send to students |
