<objective>
Ship ORG-04: an optional AI-drafted starting brand kit that persists nothing and degrades
honestly when the provider is absent.

Purpose: `GEMINI_API_KEY` is unset on every machine in this project today and there is no
`backend/.env.example` to set it in. **The unconfigured path is the default path**, so it gets
built first and tested hardest. Criterion 4's whole weight sits on "nothing applies until they
explicitly save it", and the natural implementation — reaching for `upsert_brand_kit` to shape the
response — commits. That failure is invisible to a reviewer because the UI looks correct, so the
test asserts row counts rather than a response body.

Output: `google-genai` pinned, `backend/.env.example`, a lazy-imported `draft_brand_kit`, the
draft endpoint, and a test battery that passes with no network and no key.

**No AI-SPEC is due for this phase, per D-07** — the output is entirely subjective (voice
descriptors, colours, phrases) so an evaluation contract would have no ground truth to score
against; it is never persisted without a human editing it; and it never reaches a third party,
only one authenticated POR holder in a form. Its absence is a recorded decision, not an oversight.
Phase 5's CAMPAIGN-01 is the phase that warrants one: that output goes out **to students** and
carries an explicit factual-accuracy contract, which is a real evaluation contract with a
checkable property.
</objective>

  <files>backend/app/services/org_profile_service.py, backend/app/controllers/org_profile_controller.py</files>

  <action>
Add `draft_brand_kit(org) -> dict` and the endpoint that exposes it.

**Never import the SDK at module scope.** `from google import genai` and
`from google.genai import types` go *inside* the function, wrapped in
`try/except ImportError` raising `ApiError(..., "ai_unavailable", 503)`. A top-level import in a
module reachable from `create_app()` means an uninstalled or broken SDK takes down the entire app
and the whole test suite — the same shape as Phase 2's unroutable-blueprint bug. The in-repo
precedent is `app/__init__.py`'s blocklist import.

**Order of checks.** Read `GEMINI_API_KEY` from `current_app.config` first; if falsy, raise
`ApiError("AI drafting is not configured on this server.", "ai_unavailable", 503)` before touching
the import. Then the lazy import. Then the call.

**The call.** `genai.Client(api_key=key)` and `client.models.generate_content(model=current_app.config["GEMINI_MODEL"], contents=<prompt>, config=types.GenerateContentConfig(response_mime_type="application/json", response_schema=<schema>))`.
Pass a **plain JSON-Schema dict** as `response_schema`, not a pydantic model: pydantic is not a
dependency of this project and adding it would put a second validation framework beside
marshmallow. If the installed SDK rejects a dict for `response_schema`, fall back to
`response_mime_type="application/json"` alone with the shape described in the prompt — that
fallback needs no SDK feature at all and is the safe default. Record which path was taken in the
SUMMARY.

**The prompt.** Build it from the organisation's own `name`, `type` and `bio` and ask for
`voice_tone`, `palette` (six-digit hex strings) and `sample_phrases`. **The model is never asked
for a fact** — no dates, no venues, no fees, no claims about the organisation beyond restyling
what its own bio already says. Treat the org name and bio as untrusted content inside the prompt
rather than as instructions.

**Revalidate through `BrandKitSchema`.** Parse the response text with `json.loads` and load it
through the *same* schema the manual save path uses. Do not write a second, AI-specific validator:
two validators drift, and the AI path is exactly where the weaker one would be. A model emitting
`"palette": ["<script>"]` must fail the same hex regex a human typo fails. Set `source` to
`BRAND_KIT_AI_DRAFT` on the returned payload.

**Degradation, and what never leaks.** Wrap the call and the parse in a broad `except Exception`
that raises `ApiError(<our own sentence naming the retry>, "ai_failed", 503)`. Log the vendor
exception server-side at error level; **never** put its text, the key, or any part of the vendor
response into the `ApiError` message or `details` (P-03). Never return 500 — the unhandled-exception
handler is the outcome this function exists to prevent. Allow at most one retry on a parse or
revalidation failure, then `ai_failed`.

**When the provider is unavailable or fails, return the 503 and nothing else.** Do not substitute
a hardcoded or template kit and present it as a draft (P-02). The honest answer is that drafting
is unavailable and the form works without it.

**Write nothing.** No `BrandKit` row, no `AuditLog` row, no change to `Organisation`, no
`db.session` call of any kind (P-07). The warning sign that this has gone wrong is the draft path
importing `db` at all — do not import it into this function's scope. There is deliberately **no
audit row on the draft**, because an `AuditLog` row *is* a write and the criterion-4 test asserts
that count is unchanged.

**Controller.** `@org_profile_bp.post("/orgs/<org_id>/brand-kit/draft")` with
`@can_manage_org_required`. The endpoint is deliberately **unconditional** — it works even when a
kit already exists, because regenerating is harmless when it persists nothing, and gating it
server-side would block a legitimate "start over" without adding safety. ORG-04's "for
organisations that don't have one yet" scopes who the button is *for*; the UI is what scopes the
button (04-UI-SPEC.md S7-A2). There is **no accept-draft endpoint** — a second writer is a second
place for the review rule to be forgotten.

**No rate limiter in this phase** (D-06). The caller set is authenticated POR holders acting on
their own organisation; Phase 5's CAMPAIGN-01 is the real free-tier exposure and the place to
revisit it.
  </action>
